# Асклепий · JSON-приём измерений

Геката 0.1.38: Band 11 → Bluetooth → HTTPS. Стабильные ID, зашифрованная очередь и подтверждение каждого пакета хабом. Снимок — 5 минут, базовая история — 15 минут, расширенная — час. Первое окно — 7 суток, затем перекрытие 30 минут, сон минимум двое суток. complete передаётся после полного прохода поддерживаемой истории, не после одного снимка и не при ошибке формата. Неподдерживаемые возможности перечислены в [инструкции](../../../android/HUAWEI.md). Health Connect в APK удалён, прежние данные хаба сохранены.

## Приём

`POST /api/rhythm/sync`, `Content-Type: application/json`,
`Authorization: Bearer <ключ источника>`; Origin не передаётся.
Ключ из настроек Асклепия разрешает только приём измерений, а не вход в хаб
или выполнение платных запросов. Токены хранятся на сервере как SHA-256.
После чтения тела авторизация проверяется повторно; лимит — 120 пакетов
на источник в минуту, тело до 2 МиБ. Неподходящий MIME отклоняется.

Проверка ключа: `{"type":"hello"}`. Ответ содержит `state: "ready"`,
`format: "json"`, `maxRecords: 500`, `bandSnapshot: true`, `bandExtended: true`, `bandMetrics: true`; это проверка приёмника, а не связи с часами.

Пакет содержит `records` (до 500), `deleted` (до 1000 ID) и, при необходимости,
`complete`. Последний флаг отмечает завершение синхронизации. Не ставь его,
если часть нужных запросов источника завершилась ошибкой. `reset: true` удаляет
записи этого подключения перед приёмом; для обычной синхронизации не используется.

Каждая запись: стабильный `id`, стабильное имя источника `source`, `type`,
`start`, `end`, `modified` (UTC, миллисекунды). Интервал полуоткрытый, `end > start`,
не более 7 суток. ID не должен зависеть от времени очередной отправки.
Изменения и удаления должны соответствовать исходным данным, а не предполагаться
по отсутствию записи в неполном ответе провайдера.

- `steps`: целое `value` 0…200000 за интервал.
- `heart`: непустой `samples`, элементы `{time, bpm}`, 20…300 уд/мин.
- `spo2`: `value` 0…100.
- `sleep`: `complete` (boolean), `stages` с `{start,end,stage}` внутри сна.
  Внутренние коды 0…7 определены в `summary.mjs`; коды Huawei нельзя передавать
  без проверенного сопоставления. Незавершённый сон не объявляется завершённым.
- `activity`: интервал активности.
- `band`: снимок браслета; целые `battery` 0…100, `steps` 0…1000000; `end = start + 1`. Не прибавляется к истории шагов.

Повторные ID обновляют записи с учётом `modified`; более старые данные не должны
перетирать новые. Каждая запись привязана к конкретному подключению и источнику.
При пересечении источников сводка использует их приоритеты, а не складывает шаги.

## После перехода

Миграция убирает служебную таблицу старого DB-импорта и отзывает ключи,
зафиксированные в ней. Измерения, источники, отчёты и расходы ИИ остаются.
Неиспользованные старые ключи можно отозвать в настройках. APK отменяет прежние
задания DB, удаляет сохранённое подключение и освобождает разрешение на его файл.
JSON-приём используется прямым Bluetooth-подключением Гекаты; Health Kit не подключён.


## Band extended (0.35.71)

`hello.bandExtended: true` подтверждает поддержку `stress` (value 0–100),
`activity.workout` (необязательные calories ≤100000, distance в метрах ≤10000000,
steps ≤1000000, duration в секундах ≤604800, kind 0–255; только целые неотрицательные).
`sleep.detail: "trusleep"` отмечает подробный сон: полностью покрытые им базовые записи
того же источника исключаются из суточной сводки. ID, modified и авторизация прежние.

## Band metrics (0.35.74)

hello.bandMetrics=true разрешает movement (metrics.calories/distance), sleep.metrics, sleep.dictionary (до 128 числовых полей 700013xxx), sport (workout, extensionMask, samples до 512 отсчётов). Страницы спорта не суммируются с дневными калориями/шагами и длительностью тренировок. Исходные поля activity/stress доступны в deviceFields: ограниченные hex-данные, без предположений об их значении. Они не входят в AI-сводку. Новые типы отправляются лишь после согласования возможностей приёмника. GET /modules/rhythm/api/export?day=YYYY-MM-DD выдаёт записи дня после входа, без кэширования.

## Отображение 0.35.77

Для источника `Huawei Band 11 · …` поле `movement.metrics.calories` хранит калории (cal), не килокалории. Сводка переводит в kcal делением на 1000; исходный JSON и база не переписываются. Проверено по `FitnessData` (bitmap 0x04 → calories), генератору HuaweiActivitySample (`getActiveCalories → getCalories`) и контракту ActivitySample (`getActiveCalories` в calories) проекта Gadgetbridge; это ссылка на описание формата, не зависимость приложения.

Сон только с неизвестными стадиями даёт `sleepMinutes: null`, `sleepReceived: true`, `unknownSleepMinutes`; не считается завершённым. Просмотр всех записей использует авторизованный `/api/export`.


## Обновление при открытии · 0.35.79

POST `/api/rhythm/sync` с прежним scoped bearer и `{type:"watch"}` открывает поток `application/x-ndjson`: `ready`, `ping` (120 секунд), `refresh` с UUID `id`. Одно соединение на источник; новое закрывает прежнее. Ключ проверяется перед отправкой каждого сообщения; отзыв через UI немедленно закрывает поток. Поток живёт до 30 минут, затем клиент переподключается. Origin браузера запрещён, редиректы клиента отключены.

Авторизованный POST `/modules/rhythm/api/refresh` (обычная проверка Origin/сессии хаба) создаёт временные команды для действующих источников. GET этого маршрута показывает безопасные состояния. Команды объединяются в течение минуты и всё время незавершённого запроса (до 3 минут). Отключившийся телефон получает ещё актуальную команду при подключении. Перезапуск хаба удаляет временные запросы, история измерений сохраняется.

Телефон присылает `{type:"refreshAck",id,state}` через тот же bearer-маршрут. Состояния `reading`, `queued`, `delivered`, `failed` относятся только к своему источнику и актуальному UUID. `delivered` отправляется после завершения прохода и явных квитанций всех пакетов очереди; это доставка доступных записей, а не гарантия полноты истории устройства. Новые источники и старые APK продолжают использовать прежний JSON-приём.
