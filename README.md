# NEXUS404

Личный хаб: базовая настройка сервера + Docker-платформа с чатом (4
провайдера — DeepSeek, Gemini, Claude, FlowMusic) и модульной
архитектурой (каждый модуль — свой
Docker-контейнер).

## Что уже готово

- Базовая настройка сервера (SSH, firewall, fail2ban, автообновления)
- Хаб: Docker + Caddy, доверенный HTTPS, страница входа (логин+пароль)
- Главная страница — сетка карточек модулей + чат отдельной карточкой
- Чат (`/chat`) — 4 провайдера (DeepSeek с выбором модели Flash/Pro, Gemini,
  Claude, FlowMusic), без персонажа и долговременной памяти (осознанно),
  лимиты токенов, скачивание кода из ответов
- Модульная система — свой Docker-контейнер на модуль, host-bridge вместо
  прямого `docker.sock`, единая карточка модуля (`modules/_shared/chrome.js`),
  новый модуль подхватывается сканированием, без правок хаба
- 6 модулей: технический (ключи API), системные ресурсы (CPU/RAM/диск/сеть
  + удалённые агенты), расходы AI (баланс/токены по всем 4 провайдерам),
  оповещения (журнал событий + push на телефон), финансы (карта/депозит/
  курсы валют и крипты/история операций), CheevoScope (статистика игровой
  библиотеки Steam + RetroAchievements)
- PWA (устанавливается на экран, офлайн-страница)

## Установка

Проще всего — через меню, одной командой на свежем сервере от root:

```bash
curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/menu.sh | sudo bash
```

Само склонирует репозиторий и покажет меню: базовая настройка сервера,
установка хаб-платформы, её обновление, установка агента мониторинга на
дополнительный сервер. Каждый пункт — самостоятельный, самодостаточный
скрипт с собственным сохранением прогресса; меню — просто навигация между
ними, ничего не ломается, если один из скриптов уже запускали напрямую.

### Базовая настройка сервера — отдельно, без меню

Если нужен только этот шаг — один самодостаточный файл, без внешних
зависимостей:

```bash
curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/00-base-server/nexus404-base-setup.sh | sudo bash
```

Что делает — 15 шагов подряд: DNS, swap+BBR, обновление системы, auditd,
создание sudo-пользователя + блокировка root, смена SSH-порта + firewall,
способ входа, fail2ban, apparmor, таймзона+NTP, системные лимиты,
автообновления безопасности + cron (плановый рестарт/очистка),
health-checker, финальная проверка и отчёт с данными для подключения.

**Прогресс сохраняется** в `/var/lib/nexus404-base/state` — если прервать
(например, на одной из точек ручного подтверждения) и запустить снова,
уже пройденные шаги не повторяются.

**Точки обязательной ручной проверки** — скрипт сам останавливается и просит
подтвердить в терминале, и это единственное, что нельзя убрать автоматизацией:
- после создания sudo-пользователя — зайти новым пользователем в новом окне
- после смены SSH-порта — зайти по новому порту, старый порт при этом
  остаётся открытым, пока подтверждение не получено (закрывается только
  после)
- если выбран вход по ключу — после добавления ключа, перед отключением пароля

Без этих подтверждений скрипт дальше не идёт — так исключается риск
остаться без доступа к серверу из-за проблемы на стороне провайдера
(Security Group, файрвол хостинга) или опечатки в конфиге. Автоматизировать
это нельзя в принципе — только реальный вход снаружи доказывает, что порт
действительно достижим, а не просто "слушает" локально.

### Полная автоматизация всего остального

Все прочие вопросы (DNS, имя/пароль пользователя, SSH-порт, способ входа,
таймзона, день/время планового рестарта, время health-check) можно задать
заранее переменными окружения — тогда скрипт пройдёт все шаги без единого
лишнего вопроса, кроме трёх точек проверки выше:

```bash
export DNS_CHOICE="2"                       # 1=Яндекс 2=Google 3=Cloudflare
export PRESET_SUDO_USER="deploy"
export PRESET_SUDO_PASSWORD="сложный-пароль-сюда"
export PRESET_REMOVE_ROOT_KEYS="y"          # убрать ли ssh-ключи root, если есть
export PRESET_SSH_PORT="2222"
export PRESET_SSH_AUTH_METHOD="1"           # 1=пароль 2=ключ
# export PRESET_SSH_PUBLIC_KEY="ssh-ed25519 AAAA..."  # только если метод 2
export PRESET_TIMEZONE="Europe/Moscow"
export PRESET_REBOOT_DAY="вс"
export PRESET_REBOOT_TIME="04:00"
export PRESET_HEALTHCHECK_TIME="06:00"

curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/00-base-server/nexus404-base-setup.sh | sudo -E bash
```

(`sudo -E` — обязательно, иначе `sudo` не передаст эти переменные внутрь
скрипта, запущенного от root)

Если какая-то из переменных не задана или невалидна — скрипт просто
задаст соответствующий вопрос как обычно, ничего не падает.

## Структура репозитория

```
00-base-server/     — базовая настройка сервера (описано выше)
01-hub-platform/    — Docker + Caddy + хаб (Fastify/TypeScript) + модули
```

Дальше — по мере надобности: новые модули, перенос хаба на новый сервер
одной кнопкой. Подробности по каждой части — в `01-hub-platform/README.md`.

## Локальный запуск (без curl)

```bash
git clone https://github.com/0xERR404/nexus.git
cd nexus/00-base-server
sudo bash nexus404-base-setup.sh
```
