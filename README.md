Настройка сервера, небольшой хаб с PWA и собственные модули.
Вся прикладная логика — JavaScript на Node.js 24: меню, установка,
обслуживание, сбор метрик, хаб, уведомления, финансы и чат. Python-кода в проекте нет.
Зависимостей npm, фреймворков и готовых панелей нет. «Баланс» и «Чат» используют
SQLite через встроенный `node:sqlite`; отдельная служба базы не нужна.
HTML/CSS, Compose и systemd остаются разметкой и конфигурацией.
`menu.sh` загружает Node.js и запускает JavaScript-загрузчик или локальное меню.
`bootstrap.mjs` получает полную Git-копию проекта.

Номер версии берётся из `02-hub/package.json`, виден в хабе и терминале.
[История выпусков](#changes).

## Запуск

Нужны Debian/Ubuntu с systemd, root, интерактивный терминал, Linux x64/arm64.
После публикации файлов в GitHub:

```sh
curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/menu.sh | sudo sh
```

Команда загружает весь проект в `/opt/nexus404-repo`, устанавливает отдельный
Node.js при необходимости и открывает меню. Ответы читаются из терминала;
подтверждения SSH остаются ручными. Повторный запуск обновляет Git-копию через
fast-forward, сохраняя локальные изменения при конфликте. Установленные службы
обновляются отдельно пунктом 3; один запуск загрузчика их не пересоздаёт.

Для своего публичного репозитория/другой ветки замени адрес raw-файла и параметры:

```sh
curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/menu.sh | \
  sudo env NEXUS_REPO=OWNER/REPO NEXUS_BRANCH=main sh
```

`NEXUS_DIRECTORY=/opt/my-nexus` задаёт другой каталог Git-копии. Если каталог
занят чужими файлами, другой веткой или другим origin, загрузчик остановится.
Токены и приватные репозитории в команду загрузки не добавляй: этот способ
рассчитан на публичный GitHub. [Как опубликовать проект](#github).

Локальный запуск полного распакованного архива тоже сохранён:

```sh
cd nexus-main
sudo sh menu.sh
```

Загрузчик получает Node.js 24 с nodejs.org, проверяет SHA-256 и сохраняет
его отдельно в `/opt/nexus404/runtime`. Системный Node.js не заменяется.
Системные пакеты могут иметь собственные зависимости, включая Python;
удалять их из ОС установщик не пытается.

## Базовая настройка

15 этапов: DNS → пакеты → время/NTP → swap/BBR → auditd → пользователь/root →
SSH-порт/UFW → способ входа → Fail2ban → AppArmor → лимиты → события/журналы →
обслуживание → ежедневная проверка → финальная диагностика.

Новый пользователь получает sudo. Вход и `sudo -v` подтверждаются вручную,
после чего запрещается SSH-вход root и блокируется его пароль. SSH разрешается
выбранным пользователям; основной пользователь обязателен. Конфликтующие
Include/Match останавливают изменение. Проверяются локальные аккаунты,
loopback и текущий адрес администратора; другие условия Match требуют проверки.

Старый SSH-порт остаётся до проверки нового подключения. Режим ключа отключает
пароль только после проверки ключа. Режим пароля сохраняет существующие ключи.
Подтверждения — **y/n**. Таймер отката SSH — **10 минут**; текущую сессию
сохраняй открытой до окончания проверки. Firewall провайдера настраивается отдельно.

Прогресс хранится в `/var/lib/nexus404-base/state-v2`; выполненные шаги
повторно не запускаются. Диагностика в конце выполняется всегда.
Копии изменяемых настроек находятся в `/var/lib/nexus404-base/backup.*`;
это локальные копии для настройки, полноценный резерв будет отдельным этапом.

## Обслуживание

Security-обновления устанавливает штатный unattended-upgrades. Рестартом
управляет проект: ежедневно в 02:00 при наличии `/var/run/reboot-required`.
Отдельно задаётся еженедельная плановая перезагрузка. Перед обеими задачами
за 5 минут записывается предупреждение для «Сигнала». Время — в таймзоне сервера.

Рестарт пропускается, если установка не завершена, занята блокировка проекта
или работают службы автообновления APT; следующая попытка — по расписанию.
Самостоятельная перезагрузка unattended-upgrades отключена.

После любого из этих **автоматических рестартов** через 10 минут выполняются
`apt autoremove`, `autoclean` и сокращение журнала до 7 дней. При ошибке
маркер сохраняется, попытка повторяется. Обычный ручной рестарт сам по себе
не запускает очистку. Установка и задачи обслуживания разделяют блокировку.

Через 3 минуты после загрузки и ежедневно проверяются SSH, root, sudo,
UFW, Fail2ban, auditd, AppArmor, cron, таймеры, swap, TCP, время и открытые порты.
Чужие службы автоматически не отключаются. Journald и журналы проекта
ограничены ротацией; пароли и приватные ключи в сводку не попадают.

```sh
sudo nexus404-security-check
sudo nexus404-security-check --ports
sudo journalctl -u nexus404-post-reboot-cleanup.service -n 50 --no-pager
```

При ошибке проверки SSH jail установщик ждёт готовности до 30 секунд.
Если ошибка остаётся, вывод службы сохраняется в журнал установки. Диагностика:

```sh
sudo fail2ban-client status sshd
sudo journalctl -u fail2ban.service -n 40 --no-pager
```

После исправления причины повтори пункт 1: уже завершённые шаги пропускаются.

## Docker и Caddy

Пункт 2 устанавливает Docker Engine/Compose, принимает домен и адрес сервиса,
проверяет занятость 80/tcp, 443/tcp, 443/udp и DNS, валидирует Compose/Caddyfile,
затем применяет правила активного UFW, запускает Caddy и проверяет HTTPS.
Если сертификат пока не получен, статус остаётся «не подтверждён».

Домен должен вести на сервер, порты должны быть открыты у провайдера.
Для контейнера: `http://имя-контейнера:порт` в сети `nexus404`.
Для хоста: `http://host.docker.internal:порт`, доступный из Docker.
`localhost` внутри Caddy означает сам контейнер. Пустой адрес сервиса —
тестовая страница. Хаб устанавливается отдельно пунктом 5 и занимает этот домен.

Конфигурация: `/opt/nexus404/caddy/Caddyfile`; сертификаты:
`/opt/nexus404/caddy/data`. Пункт 2 можно повторить для смены домена/направления.
Если направление ведёт на хаб, его адрес входа обновляется вместе с доменом.
После смены домена переустанови PWA с нового адреса, подключи уведомления
заново и удали старое устройство в «Сигнале».

## Применение 0.10.1

Исправлена синхронизация «Кадра»: Shikimori возвращает до `limit + 1`
записей, а за концом списка может вернуть `null`. Дополнительная запись

пустым списком и не стирает сохранённые данные.

## Обновление с 0.2.0

Распакуй полный новый архив и запусти **его** `menu.sh`.
Для существующей установки хаба выбери **5**, затем **6 → 2** для «Пульса»
и **6 → 3** для «Сигнала». Можно выбрать **6 → 1** для всего набора.
Чтобы заменить старые обработчики и сборщик, не пропускай обновление «Пульса»,
если «Пульс» уже был установлен.

При завершённой базовой настройке обработчики событий, диагностика и задачи
обслуживания переводятся на JavaScript с сохранением расписаний. Если расписание
не распознано, установщик останавливается с сообщением; базу можно продолжить
через пункт 1. Пользователь, SSH-порт и пароль хаба сохраняются.

Пункт 3 доступен в Git-клоне: чистая рабочая копия → fetch → проверка структуры новой версии → merge --ff-only →
обновление отдельного Node.js 24 → Caddy → хаб → установленные модули.
Отключённые через manifest карточки остаются отключёнными. Установщик не
перезаписывает посторонний Compose override. Базовые изменения применяются пунктом 1.
Обслуживание обновляется и без хаба; в одном проходе оно применяется один раз.
После пункта 3 меню закрывается: запусти `menu.sh` снова для загрузки нового кода.
Автоматического отката Docker после применения нет; пересоздание даёт короткий перерыв.
ZIP не содержит Git. Файлы этого выпуска ещё нужно опубликовать в исходном
репозитории, прежде чем загрузка оттуда сможет получить их.

## Уведомления на Android

1. Установи «Сигнал» через **6 → 3**.
2. Открой хаб по HTTPS на телефоне и установи PWA через кнопку/меню браузера.
3. В PWA открой **«Настройки» → «Уведомления» → «Подключить уведомления»**.
4. Разреши уведомления в браузере/Android и нажми **«Проверить»**.

Подключаются до 20 устройств. Все категории включены по умолчанию;
их можно изменить, как и время ежедневной сводки. Подробности на экране
блокировки выключены по умолчанию. Выход из хаба не отзывает Push-подписку;
удаление устройства или смена учётных данных прекращает новые отправки.

Web Push работает через службу доставки браузера, например FCM у Chrome.
Свой Firebase-проект, SDK или готовое приложение не нужны. Это зашифрованные
Push-сообщения, а не опрос страницы. При закрытом приложении уведомления
может показывать service worker. Сеть, разрешения и ограничения Android влияют
на доставку; отметка «передано Push-службе» не подтверждает показ на телефоне.

Полное выключение VPS или потерю его сети должен обнаруживать **внешний
наблюдатель**: отключённый сервер не может отправить сообщение о себе.
Такой наблюдатель в этот выпуск не входит.

## Публикация и установка из GitHub

### Что загрузить

Распакуй `nexus-main.zip` и загрузи **содержимое** папки `nexus-main` в корень
репозитория. Сам ZIP и дополнительная внешняя папка не нужны.
В корне должны лежать `menu.sh`, `bootstrap.mjs`, `menu.mjs`, `host/`,
`00-base-server/`, `01-caddy-docker/`, `02-hub/`, `03-modules/`, `test.mjs`, `README.md`
и остальные файлы архива. `.gitignore` также включён в архив.

Для команды ниже используется публичный репозиторий **0xERR404/nexus**, ветка
**main**. Загружай изменения в неё обычным коммитом; force push не нужен.
Проект не содержит паролей, подписок телефонов или приватных ключей сервера.
Финансовая база, история чата и API-ключ создаются на VPS и не входят в архив.
Рабочие данные создаются на VPS вне Git-копии; не копируй их обратно в репозиторий.

Если используешь веб-интерфейс GitHub, выбери загрузку файлов и перенеси
содержимое распакованной папки. Для существующего репозитория с прежними
исходниками удобнее Git: замени рабочие файлы новой сборкой и сделай обычный
коммит, включая удаления старых файлов. В 0.8.3 удалены папки тестов, docs/
и вложенные README: их содержимое объединено в test.mjs и корневом README.md. Каталог `.git` сохраняй.

### Установка

В SSH-терминале Debian/Ubuntu:

```sh
curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/menu.sh | sudo sh
```

Если curl ещё не установлен:

```sh
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

Дальше для нового сервера: **1 → 2 → 5**, затем **6 → 1** для всех модулей либо выбор по одному в **6**. Все файлы модулей уже
загружены; вручную переносить их не нужно. «Пульс» в подменю **6 → 2** необязателен.
Пароли, домен, SSH и расписания задаются в меню, подтверждения — y/n.

При запуске из локального полного архива `sudo sh menu.sh` использует его файлы.
Для удалённой загрузки используется отдельный `bootstrap.mjs`; Git-операции,
проверки каталога и запуск меню написаны на JavaScript.

### Другой репозиторий или ветка

Замени OWNER/REPO и ветку одновременно **в URL и переменных**:

```sh
curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/develop/menu.sh | \
  sudo env NEXUS_REPO=OWNER/REPO NEXUS_BRANCH=develop \
  NEXUS_DIRECTORY=/opt/nexus404-develop sh
```

URL предназначен для публичного GitHub, без логинов/токенов. Отдельный каталог
нужен при смене origin или ветки. Каталог исходников можно менять, но установленные
службы используют общие пути `/opt/nexus404` и `/var/lib/nexus404-*`: это не способ
запустить две независимые установки на одном сервере.

### Повторный запуск и обновление

Загрузчик повторно скачивать вручную не нужно — та же curl-команда обновляет
Git-копию и открывает меню. Локальные изменения, другая ветка, другой origin,
расхождение истории или занятый каталог останавливают обновление. `reset --hard`
и `clean` не применяются. Неудачная первая загрузка не оставляет половину проекта. Все обязательные
файлы установки проверяются до применения; ссылки вместо них не принимаются.

Для применения новой версии к установленным службам выбери **3**. Пункт 3
использует origin и текущую ветку Git-копии, обновляет отдельный Node.js,
обслуживание, Caddy, хаб и установленные модули. После этого меню закрывается:
запусти `menu.sh` снова. Изменения базовой настройки применяются пунктом 1.
Пароль хаба, его данные, SSH-параметры и Push-подписки хранятся отдельно.

Эта команда получит 0.10.1 только **после публикации** данного архива в GitHub.
Сам репозиторий этой подготовкой не изменён.

После публикации 0.10.1 выбери пункт **3** для обновления установленной платформы,
затем **6 → 5 — Баланс** для первого подключения финансов. Повторные обновления
через пункт 3 сохраняют базу операций.

Для чата выбери **6 → 4**, затем в хабе открой **Настройки → ИИ**, введи ключ
DeepSeek, сохрани и проверь подключение. Ключ в GitHub добавлять не нужно.

FlowMusic находится в том же чате. В **Настройки → ИИ** сохрани свежую сессию
FlowMusic и anon key, затем проверь подключение. Старые токены не используй.

## Минимальный хаб NEXUS404

Страница входа, главная с подключаемыми модулями и PWA для Android.
Графитовый фон, голубые акценты, компактная шапка и тонкие рамки.
Общая ширина страниц — до 1120 px; карточки перестраиваются в две колонки
на телефоне. Масштабирование и навигация с клавиатуры сохранены.

В ядре нет чата, мониторинга, уведомлений, API-ключей или host-bridge.
Чат — отдельный модуль, подключается через **6 → 4**.
Node.js 24; внешних npm-зависимостей и этапа компиляции нет.

### Установка

После базовой настройки и Docker/Caddy выбери пункт **5** главного меню.
Установщик спросит отдельные логин/пароль хаба, соберёт образ и направит
текущий домен Caddy на хаб. Если домен обслуживал другой сервис, его
направление будет заменено. Пункт 2 по-прежнему устанавливает только Docker/Caddy.

Рабочий каталог: `/opt/nexus404/hub-platform`.

- `config/auth.json` — логин, соль, scrypt-хэш и origin; пароль не хранится.
- `data/sessions.json` — хэши токенов сессий и время истечения.
- `modules/` — доверенные серверные расширения.

Контейнер работает от `node`, без Docker socket и host-bridge, без публикации
3000 наружу. Код и модули доступны только для чтения; запись — в `data` и `/tmp`.
Caddy обращается по `http://nexus404-hub:3000` в сети `nexus404`.

Пункт 3 обновляет также установленный хаб. Для ZIP-копии:

```bash
sudo sh menu.sh
# Выбери пункт 5.
```

Повторная установка сохраняет пароль и модули. Для смены пароля можно задать
`PRESET_HUB_USER` и `PRESET_HUB_PASSWORD`; для первого ввода предпочтителен
интерактивный режим. Смена учётных данных завершает прежние сессии и отзывает Push-подписки.
Автоматического отката контейнеров после неудачного обновления нет.
Старые модули и встроенный чат прежней версии автоматически не переносятся.

### Вход и PWA

Сессия действует до 30 дней и переживает рестарт. Выход отзывает её на сервере.
Cookie: HttpOnly, SameSite=Strict и Secure при HTTPS. Есть ограничение попыток,
проверка Origin для изменяющих запросов, ограничение размера формы и CSP.
`TRUST_PROXY=1` рассчитан на доступ через Caddy в доверенной Docker-сети;
не публикуй порт хаба в интернет напрямую.

На Android открой домен по HTTPS и нажми **«Установить»**. Если браузер не
предоставил системное приглашение, кнопка объяснит установку через его меню.
После установки приложение открывается отдельно, без принудительного fullscreen.
Вход можно выполнить уже в установленном приложении. В офлайне показывается
экран отсутствия связи: закрытые страницы, сессии и данные модулей не кешируются.
При изменении файлов PWA получает новый кеш автоматически. Старый удаляется;
открытую страницу после обновления перезагрузи.
Шрифты и иконки локальные; Google Fonts при открытии хаба не требуется.

### Разделение экранов

Настройки всех модулей доступны только через карточку «Настройки» на главной.
В рабочих экранах нет форм настроек, шестерёнок и ссылок «Настроить».
Фильтры, обновление показателей и действия с операциями остаются в модуле.

### Окна интерфейса

Во всём хабе и новых модулях используй модальные окна `<dialog>` с `showModal()`
и общими стилями из `app.css`. `window.alert`, `window.confirm`, `window.prompt`
и отдельные окна браузера для интерфейса не используются.
Кнопки — 28 px на ПК и 30 px на телефоне; закрытие — класс `dialog-close`,
контроль 36 × 36 px и заметный крестик 28 px.
Заголовок связан через `aria-labelledby`; закрытие и Escape отменяют действие.
При удалении начальный фокус — на «Отмена». Во время запроса повторное действие
блокируется; ошибка остаётся в окне, введённые данные сохраняются для повтора.

Разрешение уведомлений и установка PWA — системные запросы браузера:
их внешний вид определяет браузер.

### Модули · API v1

Модуль — каталог с `manifest.json` и `index.mjs`. Сам хаб устанавливается пустым.
«Пульс» из каталога исходников подключается отдельно через **6 → 2** меню;
его [установка и метрики](#pulse) описаны отдельно.
«Сигнал» подключается через **6 → 3**: [описание и Push](#signal).
«Баланс» подключается через **6 → 5**: [учёт финансов](#balance).
«Чат» подключается через **6 → 4**: [DeepSeek, FlowMusic и история](#chat).
Добавление модулей выполняется администратором на сервере; веб-загрузчика нет.
Загружаются только каталоги с именами вида `example`, `chat`, `my-module`.

`manifest.json` — все показанные поля обязательны; `enabled` принимает только
JSON-значения `true` или `false`:

```json
{
  "apiVersion": 1,
  "title": "Название модуля",
  "description": "Краткое описание",
  "enabled": true
}
```

`index.mjs`:

```js
import {modulePage, escape} from '../../src/views.mjs';

export async function handle({request, path, searchParams, user, signal}) {
  if (request.method !== 'GET' || path !== '/') {
    return new Response('Не найдено', {status: 404});
  }
  return new Response(modulePage({
    username: user.username,
    title: 'Название модуля',
    content: `<p>Привет, ${escape(user.username)}.</p>`
  }), {headers: {'Content-Type': 'text/html; charset=utf-8'}});
}
```

Необязательный экспорт `summary({signal})` добавляет живую сводку на карточку:

```js
export async function summary({signal}) {
  return {state: 'ok', items: [{label: 'Задачи', value: '3'}]};
}
```

Состояния: `ok`, `warning`, `stale`. До трёх показателей, подписи и значения —
до 24 символов. Сводки доступны после входа через `/api/modules`, без кеша.
Карточки обновляются каждые 10 секунд, опрос приостанавливается в скрытой вкладке.
Ошибка или ожидание дольше трёх секунд дают `stale`; для отмены работы используй
переданный `signal`. Экспорт необязателен, `apiVersion: 1` остаётся совместимым.

Общая карточка «Настройки» открывает `/settings/`. Модуль может добавить раздел:

```js
export const settings = {
  title: 'Название раздела',
  content: '<section>Форма настроек модуля</section>'
};
```

Разделы появляются только у включённых модулей. Адрес выбора —
`/settings/?module=example`; на странице рендерится один выбранный раздел.
`content` — доверенный HTML, как в `modulePage`: значения экранируй,
скрипты и стили подключай абсолютными путями через маршруты модуля.
Идентификаторы элементов начинай с имени модуля. API сохранения остаются
в модуле; общий вход, проверка Origin и запрет кеширования сохраняются.

После копирования в `modules/example/` перезапусти контейнер:

```bash
sudo docker compose -p nexus404-shell -f /opt/nexus404/hub-platform/docker-compose.yml restart hub
```

Карточка появится автоматически. Адрес: `/modules/example/`; `path` содержит
оставшуюся часть адреса, начиная с `/`. `user` содержит проверенный логин.
Обработчик возвращает стандартный `Response`, включая потоковый ответ;
`signal` отменяется при закрытии подключения. Тело запроса доступно через
Node IncomingMessage `request`; лимиты и формат своих API задаёт модуль.

Авторизация проверяется до вызова модуля. POST/PUT/DELETE требуют Origin хаба.
HTML, API и файлы модулей не кешируются. Скрипты и стили подключай отдельными
файлами через маршрут модуля: inline-скрипты запрещены общей CSP. `content`
в `modulePage` — доверенный HTML; внешние значения экранируй через `escape`.

Модули выполняются в процессе хаба и имеют его права. Подключай только
свой или проверенный код; это интерфейс расширения, а не песочница.
Отключённые модули пропускаются. Ошибка загрузки модуля отмечается в логе.

На ПК Backspace вызывает обычный возврат по истории браузера. Ввод текста,
открытые диалоги, сочетания клавиш и автоповтор исключены. На сенсорных
устройствах остаётся стандартная навигация браузера/PWA.

### Проверка

```bash
node --test test.mjs
```

Вход/выход, отзыв сессий, ограничения запросов, авторизация модулей и PWA
проверяются без внешних зависимостей. В Chromium проверены ширины 320–1280,
манифест, service worker, офлайн-экран и отсутствие закрытых страниц в кеше.
Физическая установка на Android и полный прогон Docker/Caddy на VPS ещё нужны.

Версия платформы — 0.10.1. Все обработчики и службы проекта используют JavaScript.

## Пульс

Отдельный модуль ресурсов сервера в стиле NEXUS404. JavaScript и Node.js без
внешних зависимостей; обновление раз в 5 секунд, без базы данных и уведомлений.

### Установка

Установи хаб через пункт 5, затем выбери **6 → 2 — Пульс**.
В хабе появится карточка. Адрес: `/modules/pulse/`; вход общий с хабом.
Пункт 4 показывает ссылку и состояние сборщика. Пункт 3 обновляет установленный
модуль после хаба. При пересоздании контейнера будет короткий перерыв.

Для ZIP-копии установка и повторное применение:

```bash
sudo sh menu.sh
# Выбери 6 → 2.
```

При обновлении сохраняется manifest установленного модуля, включая `enabled`.
Вручную изменённый Compose override не перезаписывается: установщик просит
объединить конфигурацию. Автоматического отката после применения файлов нет.

На карточке хаба каждые 10 секунд обновляются CPU, RAM и заполнение диска `/`
(либо первого доступного раздела). Если свежих данных нет, проценты скрываются.

### Показатели

- CPU: загрузка по разнице счётчиков; отдельно ожидание I/O, steal и load за 1/5/15 минут.
- RAM: занято = MemTotal − MemAvailable, с учётом освобождаемого кеша.
- Swap: занято, размер; при отсутствии — «выкл.».
- Диски: локальные файловые системы, занято, доступно и резерв. Один раздел
  показывается один раз; Docker overlay, tmpfs и сетевые диски исключены.
- Сеть: приём/отправка в байтах в секунду по интерфейсам и накопленные счётчики.
  Loopback, veth и типовые Docker-мосты исключены. VPN-интерфейсы могут отображаться
  рядом с физическими: их трафик не суммируется.
- Uptime, имя сервера, ОС, ядро, модель CPU и число логических процессоров.

Первому замеру CPU/сети нужна пара отсчётов. Недоступные данные обозначаются
прочерком. Если сборщик не обновлялся более 20 секунд, показатели помечаются
устаревшими. Графики CPU/RAM хранят последние 5 минут в памяти страницы;
при закрытии история исчезает. Скрытая вкладка прекращает опрос.

### Как устроено

`nexus404-pulse.service` запускает сборщик от отдельного пользователя
`nexus404-metrics`. Он читает `/proc` и статистику файловых систем хоста,
атомарно заменяя `/var/lib/nexus404-metrics/pulse.json`. В файл попадают только
метрики: без процессов, переменных окружения, адресов подключений и паролей.
Локальным пользователям файл доступен на чтение; в интернете — только после входа.

Служба не запускает shell-команды, не слушает портов, не обращается в сеть;
запись ограничена каталогом метрик и собственным временным каталогом.
Хаб получает каталог метрик только для чтения через Compose override.
Нет Docker socket, host PID/network и доступа к корню хоста из контейнера.
Данные и файлы модуля не попадают в PWA-кеш.

Конфигурация дополнения:
`/opt/nexus404/hub-platform/docker-compose.override.yml`.
Используй `docker compose` из каталога хаба, чтобы дополнение применялось
автоматически; одиночный `-f docker-compose.yml` его не включает.

```bash
sudo systemctl status nexus404-pulse.service
sudo journalctl -u nexus404-pulse.service -n 50 --no-pager
```

Чтобы скрыть карточку, установи `enabled: false` в JSON-файле
`/opt/nexus404/hub-platform/modules/pulse/manifest.json` и перезапусти хаб:

```bash
cd /opt/nexus404/hub-platform
sudo docker compose -p nexus404-shell restart hub
```

Это отключает модуль, но не службу сбора. Её можно отдельно остановить:
`sudo systemctl disable --now nexus404-pulse.service`.
Повторная установка/обновление запускает службу снова.

### Проверка

Из корня проекта:

```bash
node --test test.mjs
systemd-analyze verify 03-modules/pulse/nexus404-pulse.service
```

Проверены формулы CPU/RAM/сети, сброс счётчиков, диски, недоступные источники,
атомарная запись и SSH-откат с заменой системных команд заглушками.
В Chromium проверены вход, ширины 320–1280 px, графики, потеря связи,
устаревшие данные, восстановление и отсутствие метрик в кеше PWA.
Сборщик также прочитал настоящие метрики тестовой Linux-среды.
Полный запуск службы и Docker на реальном VPS ещё требует проверки.

## Сигнал

Собственный модуль оповещений NEXUS404. JavaScript, Node.js 24 и стандартный
Web Push. Общий вход с хабом; отдельного аккаунта для телефона не требуется.
Установка — **6 → 3**. Адрес — `/modules/signal/`.

Главный экран содержит статус и журнал. Сначала видны 20
событий; подробности раскрываются по нажатию, следующие записи — «Показать ещё».
Телефон, категории, сводка и устройства находятся в карточке «Настройки»
на главной → «Уведомления» (`/settings/?module=signal`). Прежний адрес
`/modules/signal/settings/` перенаправляется туда. На карточке хаба — число активных предупреждений
и устройств с действующей подпиской; устаревшие данные обозначаются отдельно.

### События

| Категория | Что отслеживается |
|---|---|
| Ресурсы | CPU >90% и доступная RAM <10% в течение 5 минут; swap >80% при нехватке RAM; OOM; диски/inode 85% и 95% |
| Службы | Docker, сборщик «Пульса», контейнеры хаба/Caddy; unhealthy; 3 рестарта за 10 минут; ошибка локальной HTTPS-проверки |
| Сертификат | До истечения ≤14 дней; критическое предупреждение ≤3 дней |
| Безопасность | SSH-входы, новый IP хаба, 10 неудачных входов за 10 минут, группировка банов Fail2ban, состояние защиты/SSH/root, неожиданные порты и изменение ключевых файлов настроек |
| Обслуживание | Ошибки обновления/проверки/очистки; необходимость рестарта; предупреждение за 5 минут до еженедельного рестарта; загрузка сервера |
| Восстановление | Устойчивое возвращение контролируемого показателя в норму |
| Сводка | CPU/RAM/диски, выявленные сбои служб, последнее зарегистрированное обновление и нерешённые предупреждения |

Большинство сбоев служб подтверждается в течение минуты. CPU/RAM — за 5 минут;
критическое заполнение диска/inode — сразу. Стандартный повтор — раз в 6 часов,
сертификат/необходимость рестарта — раз в сутки. Возврат в норму подтверждается
за минуту. Баны группируются; отдельный OOM не теряется.

Проверки ресурсов идут раз в 5 секунд, системные проверки — примерно раз в 30
секунд. События SSH/Fail2ban/обслуживания требуют завершённой базовой настройки.
«Сигнал» собирает ресурсы самостоятельно и может работать без «Пульса».
Сайт проверяется через локальный Caddy с проверкой TLS; внешнюю доступность,
сетевой экран провайдера и полный отказ VPS проверяет отдельный внешний наблюдатель.

### Телефон

Установи PWA по HTTPS → открой «Настройки» → «Уведомления» → «Подключить уведомления» → разреши
показ → «Проверить». Если Android запрещает уведомления, разреши их в настройках
приложения/браузера. После истечения подписки нажми «Переподключить».
Подписка действует и после выхода из хаба; её можно удалить с любого своего
устройства. Смена логина/пароля хаба делает старые подписки недействительными.
Сообщения, уже принятые Push-службой, отозвать нельзя.

Все категории отправляются по умолчанию. Их отключение касается Push;
события остаются в журнале. Подробности на экране блокировки включаются отдельно.
Сводка по умолчанию в 09:00 по времени сервера; при более позднем запуске
отправляется один раз в этот день. История — последние 300 событий.

Состояние проверок не обновляется успешной отправкой Push: при сбое монитора
показывается устаревшая сводка и записывается отдельная тревога.

Порядок сообщений одного устройства сохраняется и при повторных попытках.
Очередь переживает перезапуск, повторяет неудачные отправки с увеличением паузы
и хранит их до 24 часов. Удалённые/истёкшие подписки исключаются. Показ на телефоне
зависит от сети, разрешений и энергосбережения. Статус принятия Push-службой —
не подтверждение доставки пользователю. Для проверки всегда используй кнопку.

### Устройство и данные

- `host/signal.mjs` — монитор и очередь; `signal-rules.mjs` — правила.
- `02-hub/src/webpush.mjs` — общая проверка подписок, RFC 8291 и VAPID;
  `host/webpush.mjs` подключает её на сервере. Сторонних библиотек нет.
- `02-hub/modules/signal` — интерфейс, настройки и защищённые API.
- `/var/lib/nexus404-signal/keys.json` — приватный ключ VAPID, права 600.
- `/var/lib/nexus404-signal/state.json` — очередь, курсоры, состояние правил.
- `/opt/nexus404/hub-platform/data/signal.json` — категории и подписки, права 600.
- `/var/lib/nexus404-signal/public` — только открытый ключ и сводка событий,
  доступные хабу через bind mount для чтения. API требует входа.

Монитор работает от root для чтения SSH/UFW, audit и состояния Docker.
Systemd ограничивает запись каталогом модуля и блокировками; монитор не
предоставляет HTTP API и не выполняет команды из запросов хаба. Контейнер хаба
не получает Docker socket, приватный VAPID-ключ или корень файловой системы.
Push endpoint проверяется по разрешённым службам браузеров; редиректы запрещены.
Пароли, сессионные токены и закрытые страницы не передаются и не кешируются в PWA.

```sh
sudo systemctl status nexus404-signal.service
sudo journalctl -u nexus404-signal.service -n 50 --no-pager
```

Чтобы временно остановить отправку: `sudo systemctl stop nexus404-signal`.
Чтобы запретить автозапуск: `sudo systemctl disable --now nexus404-signal`.
Отключение manifest скрывает карточку, но не останавливает службу/отправки.
Повторная установка запускает службу снова. Приватные ключи при обновлении
сохраняются: их удаление потребует переподключения телефонов.

## Баланс

Личные финансы в хабе: счета, доходы, расходы, переводы и история.
Установка — **6 → 5** после хаба. Адрес — `/modules/balance/`.
Счета и категории — **Настройки → Финансы** (`/settings/?module=balance`).

### Возможности

- Карта, наличные и накопления; собственные названия и начальный остаток.
- RUB, USD, EUR. Итоги разных валют показываются отдельно.
- Доходы и расходы с категорией, датой и комментарием.
- Переводы между счетами; для разных валют вводятся обе фактические суммы.
- Изменение и удаление операции пересчитывает остатки обоих счетов.
- Месячные доходы/расходы, фильтры по счёту и типу, история по 30 записей.
- Настройка и архивирование категорий; архивные записи сохраняются в истории.
- Сводка остатков на карточке хаба. Пароли и операции не отправляются в Push.

Сначала создаются два пустых счёта RUB: «Карта» и «Накопления». Заполни
начальные остатки до первой операции. После появления операций начальный
остаток и валюта закрепляются; название и тип счёта можно менять.
Архивировать можно только счёт с нулевым остатком. Для правки его старых
операций сначала восстанови счёт. Отрицательный остаток допустим.

Общий остаток включает все записанные операции, независимо от фильтра месяца.
Доходы и расходы относятся к выбранному месяцу по всем счетам; переводы и
начальные остатки в них не входят. Дата вводится как календарная дата, без
сдвига часового пояса. Будущая дата не превращает запись в план: она тоже
меняет остаток. Проценты по накоплениям вносятся обычным доходом.

Межвалютный перевод фиксирует реальное списание и поступление; справочные
котировки не меняют суммы операций и не пересчитывают состояние в одну валюту.
Автоматического импорта старого модуля «Финансы» в этом выпуске нет.

### Данные

Прикладной код — JavaScript. SQLite доступен через встроенный в Node.js 24
модуль `node:sqlite`, без npm-пакетов или отдельной службы базы.
База: `/opt/nexus404/hub-platform/data/balance/ledger.sqlite`.
Контейнер работает от обычного пользователя; каталог создаётся с правами 700,
файл — 600. Рядом могут находиться рабочие файлы SQLite `-wal` и `-shm`.
Копирование одного открытого файла не является согласованной резервной копией.

Суммы хранятся целым числом копеек/центов. Изменение истории и отметка запроса
фиксируются в одной транзакции. Повтор той же формы после сетевой ошибки
использует прежний идентификатор и не создаёт дубль. При конфликте правок
из двух вкладок сохраняется первая, вторая получает сообщение об обновлении.
Остатки рассчитываются из истории; отдельного перезаписываемого баланса нет.

История не обрезается. Лимиты: 100 счетов и 200 категорий; сумма и абсолютный
остаток одного счёта — до 9 999 999 999,99. API требует входа и проверяет Origin
для изменений. Финансовые данные не сохраняются в браузерном хранилище/PWA-кеше.
Без связи запись операций недоступна; интерфейс помечает последние данные.

Пункт 3 обновляет уже установленный модуль. Пункт **6 → 5** можно запускать повторно:
он заменяет код, сохраняя базу и настройку видимости manifest. Отдельный
контейнер, системная служба или открытый порт для «Баланса» не создаются.
Отключение `enabled` в manifest скрывает модуль и его настройки, сохраняя данные.

### Курсы и расходы ИИ · 0.8.0

Три карточки находятся внутри «Баланса», отдельного модуля расходов нет.

- **Валюты:** USD, EUR, KZT, CNY в RUB за одну единицу. Источник — XML ЦБ РФ;
  учитывается номинал (например, курс 100 KZT делится на 100).
- **Криптовалюты:** BTC, ETH, XMR, TON в USD. Источник — CoinGecko.
- **Расходы ИИ:** DeepSeek и FlowMusic; периоды 1 час, 24 часа, 30 дней и всё время.
  Это скользящие периоды, независимые от месяца в журнале операций.

Курсы запрашивает сервер при открытой странице: ЦБ не чаще раза в час,
CoinGecko — раз в пять минут. Таймаут 6 секунд, лимит ответа 256 КиБ,
параллельные запросы объединяются. После ошибки повтор — не ранее минуты.
Последние успешные курсы сохраняются в `data/balance/rates.json`, показываются
с датой источника и отметкой отсутствия свежих данных. Ошибка котировок не
блокирует счета и операции. В браузерный кеш финансовые данные не записываются.

Необязательный Demo API key CoinGecko — **Настройки → Финансы**.
Он хранится в `data/balance/market.json` с правами 600 и не возвращается клиенту.
Ключи ИИ остаются в **Настройки → ИИ**. Публичный доступ CoinGecko ограничен
по IP; при отказе добавь Demo key. Адреса внешних сервисов фиксированы.

DeepSeek: токены берутся из API, включая входной кэш. Денежная сумма — **оценка
в USD**, диапазон между внепиковым и пиковым тарифом. Если доля кэша неизвестна,
диапазон также включает оба варианта входных токенов. В выпуске закреплены
тарифы на 23.09.2026; изменение цен провайдером требует обновления таблицы
`src/ai-usage.mjs`. Неизвестная модель, отсутствующий usage или старый ответ
не получают выдуманного нулевого расхода. Количество обращений без оценки видно.
Остаток API-счёта (`/user/balance`) — отдельные фактические данные в валюте
аккаунта, кешируется на минуту; при смене/удалении ключа прежний остаток скрывается.
Он может включать пополнения и расход вне NEXUS404 и не используется для расчёта
стоимости отдельных запросов. Стоимость FlowMusic через проверенный API пока
недоступна; отображается число логических обращений, включая неудачные.

Учёт — таблица `ai_usage` в `data/chat/chat.sqlite`, без внешнего ключа к темам.
Она не содержит промптов, ответов или секретов. Удаление переписки не удаляет
учёт; явный повтор DeepSeek считается новой попыткой, повтор HTTP-запроса не
дублируется, продолжение FlowMusic сохраняет одно обращение. Полученный usage
сохраняется сразу, даже если поток позже оборвётся. Если провайдер списал деньги,
но не прислал usage, сумма неизвестна. Прерванные перезапуском попытки также
сохраняются. Отсутствующий модуль «Чат» не мешает работе финансов.

При первом запуске нового чата оставшийся usage старой переписки переносится
один раз, без применения сегодняшних тарифов задним числом. Ранее удалённую
историю и ранее потерянные данные о повторах восстановить невозможно.
Для сохранения учёта нужна резервная копия всей базы чата.

Источники контрактов и тарифов:
- https://www.cbr.ru/development/sxml/
- https://docs.coingecko.com/demo/reference/simple-price
- https://docs.coingecko.com/docs/errors-and-rate-limits
- https://api-docs.deepseek.com/api/get-user-balance/
- https://api-docs.deepseek.com/quick_start/pricing/

## Чат

Собственный модуль на JavaScript, без SDK и npm-зависимостей.
Установка — **6 → 4** после хаба. Адрес — `/modules/chat/`.
Провайдер выбирается в чате; ключи и параметры — **Настройки → ИИ**.

### DeepSeek

Темы, история, потоковый ответ, остановка, повтор последнего ответа,
Markdown, таблицы, копирование и скачивание кода. Текстовые файлы до 64 КБ
добавляются к сообщению. На ПК Enter отправляет, Shift+Enter переносит строку.

Сохрани ключ и нажми «Проверить»: `/models` вернёт доступные модели.
Выбор обновится по ответу API, включая случай с одной моделью.
До проверки используются текущие документированные Flash/Pro.
В настройках: модель, размышление и лимит 4096/8192/16384 токена.
Проверка ключа не генерирует платный ответ. Размышление по умолчанию выключено;
`reasoning_content` не сохраняется. HTML из ответов не исполняется.

Контекст — до 80 последних сообщений выбранной темы и 96 000 символов.
Ранняя история остаётся в базе. Вопрос — до 32 000 символов, ожидание — три минуты.
Разрыв соединения отменяет HTTP-запрос, частичный ответ сохраняется.
Явный повтор после ошибки DeepSeek вызывает API заново и может расходовать токены.

### FlowMusic

HTTP-адаптер без браузера, SDK и внешних приложений. Отдельные темы,
статусы работы, локальное сохранение аудио, плеер и скачивание.
Данные тем DeepSeek в FlowMusic не отправляются и наоборот.

1. Войди в FlowMusic заново. Ранее переданные токены считаются скомпрометированными.
2. В **Настройки → ИИ → FlowMusic** введи новый refresh token и публичный Supabase anon key.
3. Сохрани сессию и нажми «Проверить». Сервер обновит токены без генерации музыки.
4. В чате выбери **FlowMusic**, создай тему и опиши музыку.

Не передавай токены в переписку или Git. NEXUS404 не автоматизирует вход в FlowMusic:
первичная новая сессия нужна от пользователя. Не используй одну вращаемую сессию
одновременно в нескольких клиентах. Проверка и дальнейшая ротация — только на backend.

Сервер получает access token через Supabase и обновляет его за две минуты до истечения.
После refresh оба новых токена и `expires_at` записываются одним файлом:
0600 → fsync → rename → fsync каталога. Параллельные запросы разделяют один refresh.
При 401 — один refresh и один повтор HTTP-запроса. Редиректы с токенами запрещены.
Перед refresh сохраняется отметка: авария во время ротации требует новой сессии,
а не повторного использования токена с неизвестным состоянием. Неполный ответ,
ошибка сети/записи и отозванная сессия также требуют нового входа.

Генерация расходует лимит аккаунта FlowMusic. Промпт — до 8 000 символов,
ожидание — до 20 минут.
«Прервать ожидание» закрывает локальный запрос: задание на стороне FlowMusic может
продолжаться. «Повторить» возвращается к сохранённому `job_id`, а не запускает музыку
заново. После перезапуска хаба также доступен явный повтор. Если POST оборвался
до получения `job_id`, автоматический повтор заблокирован: сначала проверь FlowMusic.

До восьми треков в ответе, до 64 МБ на файл. Прогресс показывается этапами, без
выдуманного процента. Аудио хранится на сервере до удаления темы; лимита общей
коллекции нет. Плеер и скачивание доступны после входа в хаб; поддержаны HTTP Range.
На аудиохранилище токены FlowMusic не отправляются. URL из `/clips` остаётся на сервере.
Разрешён HTTPS-хост `storage.googleapis.com`, без переходов на другие адреса.
Если FlowMusic вернёт другой CDN или неизвестную схему, адаптер остановится с ошибкой;
потребуется сверить новый адрес/формат, не ослаблять проверку произвольных URL.

### Контракт FlowMusic

Проверен по публичному HTTP-клиенту FlowMusic 23.09.2026:
`https://www.flowmusic.app/_next/static/chunks/pages/_app-0207edd4cf1a86c4.js`.
Код клиента используется только как справочник и не включён в проект.
Авторизованные ответы реального аккаунта в этой проверке не получены.

| Запрос | Обработка |
| --- | --- |
| `POST https://sb.flowmusic.app/auth/v1/token?grant_type=refresh_token` | `apikey`, refresh token → оба новых токена, expiry |
| `POST https://www.flowmusic.app/__api/conversation` | `parts`, `client_context`, `producer:standard`, `standard` → **job_id** |
| `GET /__api/messages/{job_id}/stream?last_id=…` | SSE с сохранением последнего ID события |
| `POST /__api/clips` | `{clip_ids}` → словарь `clips`, готовый `audio_url` |

`conversation_id` приходит событием `{id}` и сохраняется для следующего сообщения.
Событие `part`: `{index,status,part,delta}`; статусы start/delta/final.
Текст берётся из `part_kind: text`, треки — из `tool-return.content`:
`clip_id`, `clip_id_b`, `result_clip_id`, `result_upload_id`, `stems[].clip_id`.
`complete` завершает ответ, `error` фиксирует ошибку; необработанные тела ошибок
провайдера не выводятся. После complete треки опрашиваются до готовности или таймаута.
Если FlowMusic вместо музыки задаёт уточняющий вопрос, он остаётся обычным ответом.
Контекст следующего запроса включает ID беседы и последние полученные треки.

### Данные и обновление

Каталог: `/opt/nexus404/hub-platform/data/chat/`, режим 0700.
`chat.sqlite` — темы, история и состояния заданий; `deepseek.json` — ключ DeepSeek;
`flowmusic.json` — anon key, access token, текущий refresh token и срок действия.
Секретные файлы имеют режим 0600, шифрования на диске нет.
`audio/` — приватные файлы и краткие метаданные. Удаление темы удаляет её аудио.

Ключи не возвращаются через API. Поля ввода очищаются после сохранения;
секреты, история и аудио не сохраняются в localStorage или PWA-кеше.
Рабочие токены и тела ответов авторизации не пишутся в журналы.
Не включай каталог данных в архив проекта или Git.

## Кадр · Shikimori

Собственный модуль просмотра списка аниме. Подключение через официальный OAuth:
пароль Shikimori не нужен, логин в NEXUS404 остаётся отдельным. Никаких записей
в список Shikimori модуль не делает. AniLabX напрямую не читается: его изменения
появятся здесь, только если они уже попали в Shikimori.

1. Установи «Кадр» в подменю модулей и открой **Настройки → Аниме · Shikimori**.
2. Создай приложение на https://shikimori.io/oauth/applications. Название
   латиницей, например `NEXUS404`; сайт — адрес твоего хаба. Redirect URI:
   `urn:ietf:wg:oauth:2.0:oob`. Дополнительные scopes не запрашиваются.
3. В настройках хаба укажи то же название, Application ID и Secret. Нажми
   «Получить ссылку», затем «Разрешить доступ в Shikimori».
4. Скопируй выданный код, вернись в настройки и нажми «Подключить».
   Код одноразовый; заготовка подключения в хабе действует 15 минут.
5. После подключения начинается первая синхронизация. Открой «Кадр».

На карточке: обложка, русское название (либо исходное), статус, твоя оценка
и серии `6 / 12`. Нулевая оценка показывается как «без оценки», неизвестное
число серий — `?`. Поиск по русскому и исходному названиям, шесть фильтров
статуса. Все записи загружаются на сервер, на экране — по 30 для компактности.
Название открывает страницу аниме в Shikimori.

Сервер проверяет обновление раз в минуту, синхронизирует раз в час независимо
от открытого браузера. Ручная кнопка доступна через минуту после успешной
синхронизации. При ошибке следующая попытка — не раньше пяти минут; более
длинный `Retry-After` учитывается. На странице указано время последней успешной
синхронизации. Ошибка, неполная страница, дубли при изменении списка или сбой
GraphQL не заменяют сохранённый список. Ошибка записи также сохраняет прежний
файл. Смена аккаунта очищает старую копию только после успешной авторизации.

HTTP: `GET /api/users/whoami`, постраничный `GET /api/users/:id/anime_rates`
по 100 записей с обработкой дополнительной записи и конца списка; обложки — `POST /api/graphql` пакетами до 50.
Запросы последовательные с паузой не меньше 1,1 секунды. На 429/5xx до двух
повторов; автоматические повторы обмена OAuth-кода/refresh не выполняются.
Защитный предел — 100000 записей и до 1001 запроса страниц (включая конечную): при превышении сохраняется
прошлая копия, частичный импорт не публикуется.

Токены и Secret лежат только на сервере в `data/anime/shikimori.json`, права 600.
Access token обновляется перед истечением срока; при 401 выполняется один
refresh и один повтор запроса. Оба новых токена сохраняются атомарно.
Прерванная ротация требует переподключения, чтобы не переиспользовать старый
refresh token. Все данные и обложки доступны только после входа в хаб,
с `no-store`; PWA не складывает их в офлайн-кэш. Обложки передаются через
ограниченный серверный прокси без токенов, неизвестные адреса не загружаются.
Недоступная обложка заменяется заглушкой.

Документация сервиса: https://shikimori.io/oauth и https://shikimori.io/api/doc.
Реальное подключение твоего аккаунта проверяется после установки: в этой
сборке HTTP-ответы для тестов имитировались, персональные токены не использовались.

Этап пустого хаба условно соответствует 0.1.0; отдельного релиза с этим

### Правила

- 0.3.x — исправления текущего этапа.
- 0.4.0 и далее — новые возможности до стабилизации.
- 1.0.0 — проверенные установка/обновление на VPS, вход и PWA на Android,
  закреплённый интерфейс модулей, отсутствие известных критических ошибок.
- После 1.0.0: исправления повышают PATCH, совместимые возможности — MINOR,
  нарушение совместимости — MAJOR. Младшие части при этом обнуляются.

Канонический номер платформы хранится в `02-hub/package.json`.
Номер сохранения архива учитывается отдельно.
