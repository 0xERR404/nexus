### Изменения 0.35.224

### Арго: маршрутизация, сертификаты и проверка логики

- В форме пользователя появился встроенный режим «Всё через выбранное VPN-подключение». Он выбран для новых пользователей, создаваемых через интерфейс. В JSON для Happ и профиле Mihomo передаются общий маршрут TCP/UDP через выбранное подключение и запрет прямого резерва. Ранее сохранённые пользователи и профили не переключаются автоматически: для них сохранены существующие правила и прямой маршрут вне правил. Для исправления ситуации `[socks -> direct]` выбери у своего пользователя новый режим, сохрани, обнови подписку и переподключись. Один успешный пинг не доказывает, что сайты проходят через VPN.
- В каждом собственном профиле можно задать «Адреса вне правил»: VPN, напрямую или блокировка. Правила и исключения имеют приоритет. Режим теперь виден в карточке пользователя, карточке профиля и окне подписки. Если нужны отдельные VPN-направления, используй собственный профиль с явным прямым маршрутом вне правил.
- Изменение клиентского профиля, его назначения, имени пользователя и перевыпуск только ссылки не создают лишнее задание нодам. Изменение ключей, доступа, лимитов или состава подключений по-прежнему требует подтверждения ноды. Подписка не смешивает новые ключи со старой подтверждённой конфигурацией.
- Обычная форма подключения и расширенный JSON-редактор теперь одинаково проверяют соответствие SNI сертификатам ноды. Ошибка сообщает имя подключения. Неудачное сохранение не меняет настройки и ревизию.
- Нода хранит отдельные действующие сертификаты для разных IP и доменов, выбирает пару по SNI и сообщает панели все доступные имена. Добавление домена больше не удаляет действующий IP-сертификат. Старый формат с общей парой читается без ручного переноса. При обновлении пары удаляются предыдущие копии с тем же набором имён, просроченные и незавершённые пары; чужие файлы не удаляются. Предельное число разных действующих пар — 32. Сертификаты, удалённые старой версией, восстановить из воздуха нельзя: их нужно выпустить заново или импортировать.
- Выпуск для IP и домена использует разные каталоги Certbot. Таймер продлевает все сертификаты в изолированном каталоге VPN; hook применяет только зарегистрированные источники. Импорт готового сертификата не выключает продление других сертификатов. Импортированные пары нужно продлевать своим ACME-клиентом. Для штатного standalone-выпуска и продления требуется свободный доступный TCP/80; проверки браузера, редиректы и ограничения Cloudflare не должны мешать HTTP-01.

Для всех исправлений обнови **панель и VPN-ноду** до 0.35.224. Сначала обнови ноду, прежде чем добавлять второй сертификат. Пользователей и ключи пересоздавать не нужно. Публикация настроек Cloudflare, DNS, выпуск сертификатов на реальных VPS и изменение установленного Happ автоматически не выполнялись. Прямое подключение может оставаться на IP с доменным SNI; Cloudflare используется только явно выбранными Trojan XHTTP/TLS и gRPC/TLS. Проверка сертификатов остаётся включённой.

Итог локальных проверок: 195 автоматических тестов и 17 сетевых сценариев с клиентским ядром Happ 26.9.9 прошли. Отдельный сравнительный прогон с клиентским Xray 26.9.30 выявил описанное ниже ограничение gRPC.

Проверки включают сохранение/миграцию настроек, подтверждение ноды, ограничения и отзыв доступа, подписи и повтор обмена агентом, firewall/UDP-порты, внешние списки, DNS, полные подписки, сертификаты IP+домен и отказы активации. Интерфейс проверен в браузере на ширинах 1366 и 390 пикселей. Передача TCP/UDP проверяется локально ядрами Xray и Happ, включая HTTPS/HTTP2-прокси между клиентом и нодой. Это не заменяет проверку через реальную сеть Cloudflare и мобильного провайдера.

Обнаружено отдельное ограничение **клиентского** Xray 26.9.30: gRPC в локальном тесте не переподключился за 35 секунд после перезапуска ноды; журнал содержит `operation was canceled`. Это не ошибка выпуска TLS и не повод отключать проверку сертификата. В исходнике 26.9.30 повторный системный dial использует исходный контекст запроса: https://raw.githubusercontent.com/XTLS/Xray-core/v26.9.30/transport/internet/grpc/dial.go . На стороне сервера 26.9.30 входящие gRPC-подключения проверены. Для проблемы с таким клиентом доступны перезапуск подключения или другой транспорт; чужое ядро в этом архиве не патчится.

## 0.35.223 — подключения через Cloudflare

В Арго → Серверы → подключение добавлен выбор «Напрямую / ☁ Через Cloudflare». Поддерживаются существующие профили Trojan XHTTP + TLS и Trojan gRPC + TLS. Reality, Trojan RAW/TCP и Hysteria2 через обычный оранжевый прокси не поддерживаются; такие сочетания отклоняются. Настоящий адрес ноды остаётся IP, домен Cloudflare хранится отдельно. Адрес агента и развёртывания не меняется. Подписка Xray JSON для Happ получает домен, SNI, TLS с проверкой сертификата, транспорт и ключи. XHTTP использует packet-up и Host домена; сервер продолжает принимать auto. gRPC использует HTTP/2 на 443. Для XHTTP доступны HTTPS-порты 443, 2053, 2083, 2087, 2096, 8443; публичный и серверный порты совпадают. Два TCP-подключения не могут одновременно занять один порт.

Облако появляется у конкретного подключения, у сервера (подсказка показывает количество подключений через Cloudflare), в выборе подключений, диагностике и названиях профилей Happ / ссылок. Это отметка настройки, а не результат сетевой проверки или автоматического определения CDN. Обычные подключения и их имена сохраняются. Диагностика сравнивает IP выхода с настоящим адресом ноды, а не с адресами Cloudflare. Пока нода не подтвердит изменения, подписка сохраняет последний применённый вариант.

Настройка: создай A/AAAA-запись домена на IP ноды, включи Proxied и SSL/TLS Full (strict), для gRPC — Network → gRPC. В Арго укажи настоящий IP ноды, домен Cloudflare и поддерживаемый порт; SNI заполняется автоматически. На ноде необходим сертификат для домена. Один комплект TLS используется всеми TLS-подключениями ноды: новый сертификат должен покрывать все действующие SNI, иначе существующие подключения по IP могут перестать проходить проверку. Можно импортировать подходящий сертификат через настройку TLS ноды. Сам перевод DNS на Cloudflare не выпускает сертификат для VPN-ноды. Этот релиз не меняет сертификаты и настройки Cloudflare автоматически. Не включай веб-проверки браузера или кэширование на пути VPN.

После сохранения дождись «Применены», обнови подписку Happ и переподключись. Пользователей пересоздавать не нужно. Для новых портов обнови правила firewall ноды через её деплой. Mihomo поддерживает Trojan gRPC; Trojan XHTTP по-прежнему явно отклоняется для Mihomo, используй Xray JSON. Поле режима совместимо с уже установленной нодой, поддерживающей эти транспорты: серверные параметры TLS/gRPC/XHTTP остаются прежнего формата.

Документация: https://developers.cloudflare.com/network/grpc-connections/ и https://github.com/XTLS/Xray-core/discussions/4113 . Реальный путь через Cloudflare проверяется после настройки домена и сертификата; локальные проверки не доказывают доступность сети Cloudflare у провайдера.

## 0.35.222 — диагностика соединения с устройства

Арго → Диагностика: HTTP-задержка до хаба без нагрузки и при скачивании, медиана, 95-й процентиль, разброс соседних успешных проб, доля неудачных HTTP-проб, периоды недоступности и восстановление. Быстрая проверка около 30 секунд или наблюдение 3 минуты. Тайм-аут каждой пробы — 4 секунды; время восстановления оценивается по выборочным запросам, а не по журналу Happ. Загрузка ограничена 12 секундами и 32 МиБ; быстрый канал может не насытиться. Отмена, скрытие вкладки и ошибки авторизации не считаются потерей сети.

Проверка выполняется в браузере на Windows/Android. Отключи VPN для исходного замера, затем вручную включи нужный профиль Happ. Если используется выборочная маршрутизация, направь `full:домен-хаба` через выбранное VPN-подключение, обнови подписку и переподключись. Настройки Happ не меняются автоматически. Диагностика сопоставляет IP выхода с адресом выбранной ноды; совпадение не доказывает конкретный протокол. CDN, NAT, IPv6 или отдельный egress могут давать неподтверждённый результат. Не трактуй его как проверенный VPN-маршрут. IP клиента определяется сервером через существующую доверенную настройку прокси; не включай TRUST_PROXY на публичном напрямую доступном хабе.

Это не ICMP-пинг, измерение потерь UDP или пропускной способности. HTTP-задержка включает путь до хаба, HTTPS и обработку сервером. Сравнивай одинаковую сеть, режим и направление. Наблюдение работает только пока вкладка видима. 30 последних результатов сохраняются в текущем браузере; доступны подробности, удаление и JSON-отчёт. Адреса IP, VPN-ключи и ссылки подписок в отчёт не записываются. История не синхронизируется между устройствами.

Серверные конечные точки требуют входа, используют краткоживущие сеансы, ограничение запросов/трафика и несжимаемый тестовый блок. Произвольные внешние URL не запрашиваются. Обновление панели достаточно; обновление ноды и пересоздание пользователей для этой функции не нужны.

### Устойчивость VPN-соединений · 0.35.218

- Для TCP-профилей добавлен режим «Устойчивое соединение», включённый по
  умолчанию. Проверки TCP начинаются после 45 секунд простоя с интервалом
  15 секунд; лимит неподтверждённых данных — 60 секунд. На клиенте не
  задаются Linux-специфичные алгоритмы. Режим «Настройки ядра» позволяет
  вернуться к штатным параметрам транспорта.
- Нода проверяет доступность BBR и разрешение использовать его непривилегированной
  службой. BBR применяется к TCP-сокетам VPN и общему исходящему TCP-трафику при
  наличии устойчивых подключений. Если он недоступен, остаётся системный алгоритм.
  Установщик пробует загрузить tcp_bbr и сохраняет автозагрузку при успехе.
  Общие sysctl, очереди интерфейсов, SSH и другие службы не перенастраиваются.
  В карточке ноды показывается доступность BBR.
- Клиент gRPC проверяет простаивающее соединение через 60 секунд и ждёт ответ
  до 20 секунд. Проверки без потоков отключены; слишком частые проверки не
  включаются, чтобы не провоцировать закрытие соединения сервером.
- Для Hysteria 2 без ручных параметров используются BBR standard, KeepAlive
  10 секунд и автоматическое определение MTU. Сохранённые ручные значения,
  включая отключённый KeepAlive и Brutal, не перезаписываются. Кнопка
  «Для устойчивого соединения» задаёт согласованный набор BBR/QUIC и сохраняет
  маскировку, пароль и диапазон портов.
- Группы резервирования в Xray JSON проверяют только используемые подключения
  каждые 15 секунд вместо 60. Выбор по задержке применяется к новым соединениям;
  уже открытый TCP-сеанс не переносится на другой сервер. Прямой обход VPN при
  отказе не включается самопроизвольно — действует выбранная маршрутизация.

Применение: обновить хаб и VPN-ноду из полного архива, дождаться статуса
«Применены», обновить подписку Xray JSON в Happ и переподключиться. Отдельные
URI и другие форматы подписки не переносят все параметры транспорта.

Проверки: формы на ПК и телефоне, сохранение и чтение настроек, формирование
подписки, совместимость со всеми семью профилями, реальная локальная передача
TCP/UDP через Xray 26.9.30 и клиентское ядро Happ 26.7.28. Linux BBR проверен
через имитацию доступности и разрешений; на пользовательских VPS команды не
выполнялись. Фактическое снижение пинга через интернет не измерялось.

Выявленное ограничение: в проверенном ядре Happ 26.7.28 Trojan может отклонять
крупную первую отправку TCP с ошибкой «buffer is full». Это воспроизводится и
в режиме штатных настроек. Арго не исправляет внутренний буфер стороннего
клиентского ядра; для такого трафика следует использовать VLESS или Hysteria 2.
Большая передача после установления протокола проверяется отдельно. Стороннее
приложение Happ и его ядро этим архивом не заменяются.

Основания для параметров: [Xray Sockopt](https://xtls.github.io/en/config/transports/sockopt.html),
[gRPC](https://xtls.github.io/en/config/transports/grpc.html),
[QUIC](https://xtls.github.io/en/config/transports/finalmask.html).

### Устойчивость связи панели с нодой · 0.35.217

- Очередь событий делится по фактическому размеру UTF-8 запроса до лимита панели.
  Большой накопленный журнал больше не блокирует обмен и продление разрешения VPN.
- Длинные текстовые поля событий, включая уже сохранённые записи, приводятся к
  ограничениям панели. Подтверждение потерянного ответа принимается и после
  уменьшения повторного пакета; события не теряются и не дублируются.
- Максимальная пауза между неудачными попытками сокращена с 60 до 15 секунд плюс
  до секунды случайной задержки. Явный Retry-After панели имеет приоритет.
  После успеха возвращается обычный интервал 5 секунд. Запросы не перекрываются.
- Планирование использует монотонное время. Ошибка сбора показателей или записи
  сообщения о потере связи не прерывает цикл повторных подключений.
- Обновление VPN-ноды теперь копирует и обновлённый агент обмена перед его
  перезапуском. Нужно обновить VPN-ноду из этого архива; обновления панели одной
  недостаточно. Ключи, пользователи и подписки сохраняются.

Проверка канала: локальный HTTPS с проверкой сертификата и подписей, ошибки DNS,
зависший TLS, потерянный/оборванный ответ, HTTP 429/503, недоверенный сертификат,
слишком большой ответ, повторы после перезапуска и доставка накопленной очереди.
В модели полной цепочки агент → панель → нода обрыв на 100 секунд переживается
без перезапуска VPN; при обрыве 160 секунд VPN останавливается по истечении
разрешения и восстанавливается после возвращения связи. Разрешение по-прежнему
действует 120 секунд: длительная недоступность панели требует остановки VPN.
Фактические задержки и потери между пользовательскими VPS не измерялись.
IPv6-резервирование проверено с подменой соединителя: эта среда запрещает IPv6
loopback. Linux-службы на пользовательских серверах не запускались и не менялись.

- Статус связи определяется по свежему отчёту ноды, отдельно от времени последнего

Проверки: сохранение и перенос настроек, права доступа и смена ключей, лимиты,
подписки, источники и маршрутизация, откат конфигурации, учёт трафика, восстановление

не устанавливались. Linux-службы и правила firewall проверялись по коду и

### Совместимость Trojan и обновление VPN-ноды · 0.35.215

Нода сообщает свою версию и поддерживаемые профили отдельно от версии Xray.
Арго показывает версию в карточке сервера и проверяет поддержку транспорта при
сохранении подключения и конфигурации. Явно неподдерживаемый профиль не сохраняется;
отсутствие данных у старой ноды не выдаётся за доказанную несовместимость.
Исходная причина отказа сохраняется. Для нод без сведений о новых профилях
показывается подсказка о раздельном обновлении панели и ноды.

Установщик переносит полный набор зависимостей VPN, проверяет записанные файлы
и после перезапуска ждёт отчёт именно новой версии процесса. Старый отчёт или
просто активная служба больше не считаются подтверждением обновления. Работающие
ключи, сертификаты и подписки сохраняются. Для ошибок задания добавлены конкретные
причины: неизвестный профиль, неверный путь XHTTP, имя gRPC, список пользователей.

Для установки исправления обновляются и хаб, и VPN-нода из этого полного проекта.
Обновление одного хаба не меняет файлы на удалённом VPS. Реальные локальные
подключения Trojan TCP / XHTTP / gRPC проверяются с ядром Happ; установка на
пользовательские серверы в рамках подготовки архива не выполнялась.

### Расширенные настройки Hysteria 2 · 0.35.214

Арго → Серверы → Подключение → Hysteria 2. Все блоки параметров открыты:

- Скорость: автоматически, BBR (осторожный / обычный / агрессивный), Brutal.
  Для Brutal задаются загрузка и отдача клиента в Мбит/с; направления на ноде
  пересчитываются автоматически. Это настройка пропускной способности, не обещание скорости.
- Salamander: включение и пароль маскировки. Пароль передаётся в ноду и подписку.
- Смена UDP-портов: до 8 диапазонов / 1024 портов, интервал от 5 секунд,
  совместимость с Happ на ядре 26.7.28 или Xray 26.9.30. Форматы отличаются;
  выбирай по версии ядра своего клиента. Основной порт не входит в диапазон.
- Страница HTTP/3: обычный ответ 404 либо своя HTML-страница до 2048 байт.
  Страница предназначена для неавторизованных посетителей, остаётся только на сервере
  и несовместима с включённой маскировкой Salamander.
- Тайм-ауты UDP / QUIC, KeepAlive, определение MTU, начальные и максимальные
  окна потока и соединения, максимальное число входящих потоков.

Обновление: сначала VPN-нода, затем хаб. Параметры существующих подключений
не меняются сами. После сохранения дождись «Применены», обнови подписку Happ.
Для полного набора клиентских параметров используй Xray JSON.
Mihomo получает Salamander, смену портов, скорости, профиль BBR и окна QUIC;
отдельные URI — подключение, маскировку и диапазон портов, без полной настройки QUIC.

После изменения диапазона портов повтори деплой VPN-ноды. Установщик добавляет
UDP-порты в активный UFW и создаёт отдельную таблицу nftables для перенаправления
на основной порт. Чужие таблицы и правила не очищаются. Отдельная служба применяет
переадресацию при загрузке до запуска VPN; процесс VPN не получает CAP_NET_ADMIN.
Нода проверяет подтверждённый план текущей загрузки и не публикует новую конфигурацию
со сменой портов до применения переадресации. При отказе сохраняется прежнее
работающее подключение с учётом отозванных доступов. Порты в firewall провайдера
нужно разрешить отдельно. При удалении диапазонов повторный деплой удаляет только
нашу переадресацию; добавленные разрешения UFW автоматически не удаляются.

### Настройки VPN в целом

- Подключения: имя, нода, адрес, порт, SNI, включение / отключение.
- VLESS: RAW/TCP, XHTTP, gRPC с Reality; целевой домен и fingerprint,
  путь XHTTP или имя службы gRPC. Ключи создаются автоматически.
- Trojan: TCP, XHTTP, gRPC с TLS; путь XHTTP или имя службы gRPC.
- Hysteria 2: QUIC / UDP с TLS и расширенными параметрами выше.
- Пользователи: имя, разрешённые подключения, срок, лимит трафика,
  профиль маршрутизации, включение / отключение, удаление, история расхода,
  перевыпуск ссылки подписки и замена ключей.
- Серверы: подключение агента, страна, состояние применения, TLS, учёт трафика,
  редактор конфигурации (порт, SNI, транспортные параметры, DNS, direct/block).
- Маршрутизация: DNS, домены, подсети, geosite/geoip, исключения,
  прямой выход / блокировка / VPN, группы резервирования и внешние списки.
- Подписки: Xray JSON для Happ, Mihomo, Base64, отдельные ссылки и QR.
  Trojan XHTTP требует Xray JSON; Mihomo этот транспорт не поддерживает.
- На ноде: выпуск / импорт / продление TLS, настройка firewall и смены портов.

Локально проверяются ядро ноды 26.9.30 и установленное ядро Happ 26.7.28:
TLS, TCP и UDP внутри туннеля, BBR, Brutal, Salamander, смена портов во время
передачи данных, неверные пароли и отзыв доступа. Правила Linux проверены
автоматическими тестами генерации и применения; на пользовательском VPS этот
архив автоматически не разворачивается.


### Выбор транспорта Trojan · 0.35.213

Арго → Серверы → Добавить подключение / Изменить → Профиль:
Trojan TCP · TLS, Trojan XHTTP · TLS или Trojan gRPC · TLS.
Для XHTTP настраивается путь, для gRPC — имя службы. Значения передаются
в конфигурацию ноды, Xray JSON для Happ и отдельные ссылки подключений.
Существующий профиль Trojan сохраняет TCP; пароли не меняются.

Обнови хаб и VPN-ноду этим архивом перед выбором нового транспорта.

чтобы не подменить XHTTP обычным TCP и не потерять правила маршрутизации.


### Порты при деплое VPN-ноды · 0.35.212

Установка и обновление VPN-ноды автоматически добавляют в активный UFW
правила 443/tcp и 443/udp. Из последнего задания ноды также берутся порты
включённых подключений: UDP для Hysteria 2, TCP для VLESS и Trojan.
На первой установке можно указать дополнительные порты; пустой ответ
применяет стандартный набор. Обновление выполняет этот шаг без вопросов.
Существующие правила не удаляются, повторный деплой использует UFW allow.

Неактивный UFW не включается; для другого firewall и панели провайдера
показывается список портов, которые нужно разрешить самостоятельно.
После смены порта в Арго повтори деплой ноды либо открой новый порт вручную.
Изменение относится к установщику VPN-ноды; обновлять хаб ради портов не требуется.

### Подтверждение ключей в подписке · 0.35.211

Подписка проверяет не только применённый транспорт, но и подтверждённые нодой
ключи и разрешённые подключения пользователя. Раньше новый пользователь,
замена ключей или добавленное подключение могли попасть в Happ до применения
на ноде. Теперь такие подключения ожидают подтверждения; неизменённые
подтверждённые подключения продолжают выдаваться. В снимках подтверждения
хранятся отпечатки ключей, а не дополнительные копии паролей.

После обновления хаба старые снимки без данных о доступе ожидают свежего
обмена с нодой. Менять ключи или пересоздавать пользователя не нужно.
Дождись «Применены», затем обнови подписку и переподключись в Happ.
Проверены передача параметров через обмен с нодой и все форматы подписок;
TCP/UDP и авторизация также проверены с клиентским Xray 26.7.28 из Happ
и серверным Xray 26.9.30. Доступность конкретного VPS этими тестами не подтверждается.

### Шаблон Hysteria 2 · 0.35.210

Генератор ноды использует settings.clients с индивидуальным auth, version: 2,
disableUDP: false и sniffing HTTP/TLS/QUIC с routeOnly: false. Транспорт —

### Домены и IP в маршрутизации · 0.35.152

Обнови панель на хабе из распакованного проекта:
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-panel`.
Перезагрузи страницу Арго. В разделе «Маршрутизация» открой профиль:
каждый блок теперь содержит отдельные поля «Домены и geosite» и
«IP, подсети и geoip», направление и переключатель исключения.

В первое поле можно вставлять `geosite:telegram`, `domain:telegram.org`,
`domain:t.me`, `full:whoer.net` или обычный домен (включая его поддомены).
Во второе — `geoip:telegram`, `geoip:facebook`, IP и CIDR для IPv4/IPv6.
Принимаются записи по одной на строке, строки с JSON-кавычками и запятыми,
а также целые JSON-массивы. Незавершённый JSON-массив выдаёт ошибку;
вставлять целый фрагмент конфигурации с обоими полями в одно поле не нужно.

Старые правила сохраняют направления, исключения и порядок. Блоки можно
добавлять и перемещать. Генератор объединяет соседние однотипные условия
с одинаковым направлением в массивы `domain` и `ip`; доменные и IP-условия
никогда не объединяются в один объект (в Xray это означало бы AND).
Для «Через выбранное VPN-подключение» итоговый `outboundTag` ссылается
на реальное подключение профиля, а не на несуществующий тег `proxy`.
Сайты вне правил по-прежнему идут напрямую. При наличии IP-правил Xray
использует IPOnDemand, чтобы завершающее DIRECT не обходило проверку IP
при обращении к домену. В Mihomo IP-правила также разрешают DNS-проверку.

Группы `geosite` и `geoip` выполняются клиентом: в его geosite.dat/geoip.dat
должны присутствовать выбранные имена групп. Подписка Xray передаёт правила,
но сама не устанавливает базы Happ. При ошибке отсутствующей группы обнови
геобазы в приложении. В экспорте Mihomo включается geodata-mode и задаются
базы Loyalsoldier: https://github.com/Loyalsoldier/v2ray-rules-dat.
Нода для этих клиентских правил не требует установки геобаз.

После сохранения обнови подписку в Happ и переподключись. Ноду для этой
функции обновлять не требуется; исправления стабильности из версии 150
включены в полный архив и устанавливаются отдельно через `--vpn-update`.

### Проверка стабильности VPN · 0.35.152

На VPN-ноде из распакованного проекта запусти
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-check`.
Проверка длится около трёх минут: оставь в Happ одно подключение и открывай
проблемный сайт. Команда сохраняет путь к отчёту в терминале. В отчёте —
состояние служб и число их перезапусков, свежесть отчёта VPN, срок разрешения
от хаба, порты firewall и повторные обращения ноды к Whoer/Gstatic.
Ключи, пароли, пользователи и полные конфигурации в отчёт не попадают.
Проверка не меняет firewall, конфигурацию и не перезапускает службы.
HTTP 403/429 означает ответ сайта, а не потерю соединения. Запросы с ноды
не подтверждают работоспособность участка Happ → нода или клиентских правил.

Для установки исправлений на существующей VPN-ноде:
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-update`.
Обновление однократно перезапускает VPN-службу. Для изменений 150 хаб
обновлять не обязательно, если уже установлена версия 149.
После временной ошибки запуска та же версия автоматически повторяется
через 30 секунд; при повторных ошибках интервал растёт до 5 минут.
Новая конфигурация или обновление сертификата проверяется без этой задержки.
Одиночная ошибка чтения счётчиков повторяется в пределах прежнего общего
тайм-аута 10 секунд. Неверные счётчики и постоянный сбой по-прежнему останавливают
передачу, сохраняя ограничения учёта. Готовность запуска ядра ожидается не более
10 секунд до остановки неудачного запуска. Продление от хаба остаётся обязательным:
при истечении двухминутного разрешения VPN останавливается.

Персональный хаб с PWA и 17 модулями. Сервер, установщик и обслуживание — JavaScript / Node.js 24. Талос — Android-помощник на Java: деньги и Huawei Band 11. HTML/CSS, SQL, shell и конфигурация развёртывания остаются в проекте там, где нужны.

Рабочий выпуск: сервер, 17 модулей, установщик, обслуживание, PWA и готовый APK Талоса 0.1.66/code67. Исходники Android, тесты, история изменений и отчёт проверки находятся в отдельном архиве development; для установки они не нужны. Мозаика главной сохранена. Настройки сгруппированы в боковом меню; на телефоне — компактный выбор раздела. Фоны выбираются по миниатюрам. Внутренние страницы не содержат дублирующую шапку; при отключении музыкального модуля используется общая современная навигация.

## Установка

Debian/Ubuntu, root или sudo. Для полного хаба — домен с DNS на сервер; агенту и VPN-ноде собственный домен не нужен. Полный проект должен быть опубликован в репозитории, иначе команда получит прежнюю версию:

```sh
curl -fsSL https://raw.githubusercontent.com/0xERR404/nexus/main/menu.sh | sudo sh
```

Первичная установка: **Подготовка сервера → Базовая настройка**, затем **Подготовка сервера → Docker и Caddy**, **Хаб и модули → Установить / настроить хаб**, **Хаб и модули → Модули** (все или по одному). Пароли, домен и SSH задаются в меню. Если curl отсутствует: `sudo apt-get update && sudo apt-get install -y curl ca-certificates`.

Из полного распакованного архива: `sudo sh menu.sh`. Файлы архива лежат непосредственно в корне; при публикации переноси всё содержимое, включая удаления старых файлов. Не копируй серверные данные, пароли и ключи подписи в репозиторий.

## Обновление

В Git-установке повтори команду запуска и выбери **Обновления → Получить и применить обновление из Git**. Обновляется ядро и уже установленные модули; вход, данные и настройки хранятся отдельно. Локальные изменения и расхождение веток останавливают обновление — загрузчик не делает `reset --hard` и `clean`.

Для ZIP-установки распакуй полный новый выпуск и выбери **Обновления → Применить этот выпуск**. Сначала сделай резервную копию. Не смешивай ядро и модули разных выпусков. APK устанавливай поверх прежней версии с тем же сертификатом; удаление приложения уничтожает его локальные ключи и очередь.

## Удалённый VPS · агент или VPN-нода

Из распакованного project на другом VPS:

```sh
sudo sh menu.sh --remote
```

Выбери **1 — агент** или **2 — агент + VPN-нода**. Прямые команды: `sudo sh menu.sh --agent` и `sudo sh menu.sh --vpn-node`. Панель Арго устанавливается отдельно **на хабе**: `sudo sh menu.sh --vpn-panel`.

1. В Атланте существующего хаба создай одноразовый код для нового VPS.
2. В мастере введи HTTPS-адрес хаба и код. У самого VPS домен не запрашивается. Адрес хаба может быть IP с действительным доверенным TLS-сертификатом на этот IP; проверка сертификата обязательна. Время на VPS должно быть синхронизировано.
3. Скрипт установит необходимые пакеты, служебные аккаунты, файлы, регистрацию и автозапуск. Агент не открывает порт управления. Для VPN добавляется ядро на ноде; хаб, Docker, Caddy и npm-пакеты там не устанавливаются.
4. Для Reality достаточно IP ноды и параметров Reality в Арго. Его SNI/target — выбранный внешний TLS-сайт, а не обязательный собственный домен.
5. Для Trojan / Hysteria 2 мастер предлагает TLS на публичный IP через совместимый Certbot либо импорт каталога с `fullchain.pem` и `privkey.pem`. Собственный домен — только дополнительный вариант. IP-сертификату Let’s Encrypt нужен поддерживаемый Certbot и свободный доступный TCP/80 для выпуска и продления. Если системный Certbot старый или отсутствует, мастер автоматически установит Certbot 5.8.0 в отдельное окружение; системный пакет не заменяется. Нужен Python 3.10+ (Debian 12+ / Ubuntu 22.04+). Проверку TLS в клиентах не отключать.
6. Выбранные VPN-порты добавляются только в уже активный UFW. Иначе мастер перечислит порты для твоего firewall; firewall провайдера настраивается отдельно. Скрипт не включает новый firewall и не меняет SSH-порты.
7. В Атланте проверь связь и настрой обслуживание; события поступают в Гермес. В Арго создай подключения, затем пользователей и подписки. Подробности — `development/docs/VPN.md`.

**Базовая настройка независима:** раздел «Подготовка сервера → Базовая настройка». Мастер удалённого VPS не перенастраивает SSH, администраторов, swap, DNS, системный аудит и автоматические обновления. На сервере без выполненной базы задачи обслуживания первоначально выключены; включай их в Атланте и дождись подтверждения. Уже принятое расписание сохраняется и работает без хаба. Часовой пояс, заданный в Атланте, применяется ко всему VPS.

**Повторный запуск / обновление:** раздел «Обновления»: получение из Git или применение распакованного полного ZIP-выпуска. Прямые команды роли также сохранены. Ключ, очередь событий, учёт VPN, сертификаты и расписания сохраняются. Enter на шаге TLS сохраняет текущую пару. Режим «агент» на существующей ноде обновляет только агент; для обоих компонентов выбери «агент + VPN-нода». Не копируй `/var/lib/nexus404-agent` на другой VPS.

Собственный таймер `nexus404-vpn-cert-renew.timer` проверяет продление четыре раза в сутки тем же Certbot; фиксированный hook передаёт сертификат ноде. ACME-данные хранятся отдельно в `/var/lib/nexus404-vpn/acme`, чужие сертификаты и таймеры не меняются. Переход на импорт отключает этот таймер. Для импортированной пары продление обеспечивает твой ACME-клиент: после обновления вызвать `sudo /usr/local/bin/nexus404-node /opt/nexus404/host/vpn-cert.mjs /абсолютный/каталог`. Клиентские приложения должны доверять CA сертификата.

Через 90 секунд без связи хаб отмечает сохранённые метрики устаревшими. События накапливаются и доставляются с дедупликацией. История метрик — 7 дней; журнал — последние 5000 событий каждого сервера. Отзыв доступа блокирует обмен, но не отменяет уже принятое локальное расписание: сначала отключи нужные задачи, дождись ACK и только затем отзывай ключ.

При временном сетевом сбое регистрация повторяется до трёх раз с тем же ключом и новой подписью запроса. Адреса IPv4/IPv6 проверяются до передачи кода; не отвечающий TLS-адрес не мешает другому рабочему адресу. DNS, соединение, TLS и ответ хаба имеют отдельные ограниченные ожидания. Ошибка объясняется прямо в меню; секреты в неё не включаются. Ошибка кода/сертификата, перенаправление и ограничение частоты не запускают три автоматических повтора. На незавершённой установке можно исправить HTTPS-адрес и код без удаления ключа.

Диагностика: `sudo systemctl status nexus404-agent` и `sudo journalctl -u nexus404-agent -n 50`; для VPN — `nexus404-vpn`. Секреты в `/var/lib/nexus404-agent/credentials.json` не публиковать. Автотесты не заменяют проверку установки на выделенном VPS и реальных VPN-клиентов.

## Талос: деньги и браслет

В Плутосе создай источник и перенеси его HTTPS-адрес/ключ в APK. Выбери пуши или SMS с точным списком отправителей. Для Сбера используй стиль **Стандарт**. Талос распознаёт проверенные форматы, передаёт сумму и магазин; баланс и коды входа не отправляются. Покупки могут записываться автоматически; поступления и возвраты требуют отдельно включённого правила источника. Переводы не считаются покупками. Неизвестные форматы не угадываются.

Для браслета создай отдельный ключ в Асклепии, укажи его в Талосе и подтверди системное сопряжение Android. Далее используются сохранённое устройство, Bluetooth LE/GATT и защищённый сеанс Huawei. Аккаунт Huawei, Health Connect и Gadgetbridge не нужны.

Опрос: снимок шагов/заряда — примерно 5 минут, базовая история — 15 минут, расширенная — час. Кнопка «Прочитать сейчас» запрашивает полный проход. Android может задерживать работу. Уведомления и музыка обрабатываются по событиям, последовательно с обменом данными.

Плеер на браслете управляет системными медиасессиями телефона. Play без активной сессии передаётся Android; запуск принудительно остановленного приложения или уничтоженного браузера не гарантируется. Отдельного Орфея, Гермеса, загрузки папок и Health Connect в нынешнем APK нет. Ранее выданные ключи этих функций можно отозвать в настройках соответствующих модулей; серверный API оставлен для совместимости.

## Важные особенности

- **Вход:** HTTPS, пароль; passkey и второй фактор настраиваются в хабе. Сохрани коды восстановления отдельно. PWA использует тот же вход.
- **Ника:** Steam Web API и RetroAchievements. QR-входа и имитации клиента Steam нет. Недоступность достижений одной игры не означает отзыв ключа; прежние данные сохраняются при ошибках.
- **Орфей:** общий плеер сохраняется при переключении модулей. Предзагрузка текущего и следующего трека ограничена по памяти; большие файлы воспроизводятся потоком. Завершение браузера Android не равно обычному скрытию страницы.
- **Дионис:** наличие пиров и доступность сети влияют на начало воспроизведения. MKV — контейнер, совместимость зависит также от кодеков и серверной обработки ffmpeg. Загрузку нельзя гарантировать для раздачи без доступных пиров.
- **Дедал:** стартовый файл выбирается из релиза, название не обязано быть `install.sh`. Копируй готовую команду из карточки. Архив проверяется SHA-256, отключение установки отзывает ссылку; скачивание не доказывает успешный деплой. Серверного `git push` нет.
- **Мнемосина:** собственные файлы имеют корзину. Удаление файла другого модуля выполняется через его обработчик и может быть окончательным; проверяй подтверждение.
- **Асклепий:** счётчик браслета не суммируется с интервальными шагами. Источники имеют приоритеты; отсутствующие измерения не заменяются нулями. Подробный сон и тренировки требуют проверки на реальном устройстве. Экспорт JSON за дату включает сохранённые дополнительные поля.
- **Отчёты DeepSeek:** отправляется числовая сводка; нужны закрытые сутки, завершённый сон и синхронизация. Автоматика отключена по умолчанию. После неопределённого результата платного запроса повтор — только явно; расходы учитываются в Плутосе.

## Феникс · резервные копии

Ручное и ежедневное создание зашифрованного архива, срок хранения,
уведомление об ошибке и опциональная отправка на отдельный сервер по SSH.
Автотест восстанавливает искусственную зашифрованную копию и проверяет прежний вход, данные Асклепия, ключ источника и байты файла. Реальная копия VPS и все модули требуют отдельного приёмочного прогона. На отдельной тестовой машине с
распакованным исходным ZIP и Node.js 24 запусти:

```sh
node tools/backup/restore-smoke.mjs /путь/копия.nexus /путь/ключ
```

Команда распакует архив во временный каталог, запустит хаб только на
`127.0.0.1`, запросит пароль без отображения и проверит вход и открытие
подключённых модулей. При включённом втором факторе этот автоматический парольный сценарий
не подтверждает вход: нужна отдельная тестовая установка с ручной проверкой
passkey/кода через браузер. Используется код из распакованного ZIP, фоновые задачи и внешние запросы
отключены. Тест не переключает
действующий сервис и удаляет временную установку по завершении.

Сначала создай ключ по разделу ниже и настрой расписание (пример: 14 дней):

```sh
sudo /usr/local/bin/nexus404-node /opt/nexus404/tools/backup/backup-schedule.mjs install \
  /srv/nexus404-backups /root/nexus404-backup/key 14
sudo systemctl status nexus404-backup.timer
```

Срок — 2–365 дней, по умолчанию 14; минимум две последние успешные копии
сохраняются независимо от срока. Таймер запускается ежедневно в 03:30 по
времени сервера с задержкой до 10 минут. Пропущенный запуск выполняется после
включения таймера. Конфигурация — `/etc/nexus404-backup.json`.
Остановка расписания: `sudo systemctl disable --now nexus404-backup.timer`.
Удалённая отправка требует предварительной настройки расписания этой командой.

Для внешнего хранилища подготовь отдельный сервер с SSH-доступом, каталогом
для копий и ключом SSH только для этой задачи. Убедись, что его ключ хоста
в `known_hosts` пользователя root, затем настрой удалённую отправку:

```sh
sudo /usr/local/bin/nexus404-node /opt/nexus404/tools/backup/backup-schedule.mjs remote \
  backup@backup.example.net /srv/nexus404 /root/.ssh/nexus404-backup
```

После локального создания архив загружается с временным именем, удалённая
контрольная сумма сверяется с локальной и файл получает окончательное имя.
При ошибке удалённой отправки локальная копия сохраняется, старые копии не
очищаются, а «Гермес» получает событие. Срок хранения действует на оба сервера.

## Ручная резервная копия

На установленном сервере один раз создай отдельный 32-байтовый ключ и сохрани его
в защищённом месте вне VPS. Без этого ключа восстановить архив нельзя:

```sh
sudo install -d -m 700 /root/nexus404-backup /srv/nexus404-backups
sudo sh -c 'set -C; umask 077; openssl rand 32 > /root/nexus404-backup/key'
sudo /usr/local/bin/nexus404-node /opt/nexus404/tools/backup/backup.mjs \
  /srv/nexus404-backups/manual-$(date -u +%Y%m%dT%H%M%SZ).nexus \
  /root/nexus404-backup/key
```

Скрипт требует root, установленный хаб и существующий ключ с правами 0600.
Он останавливает хаб, Гермес и Caddy, снимает `config`, всё `data` (включая
SQLite, файлы и секреты модулей), установленные модули, Compose, состояние
Гермеса и настройки Caddy с сертификатами. Поток tar шифруется AES-256-GCM.
После копирования работавшие сервисы запускаются снова. Во время копии
веб-интерфейс и другие сайты этого Caddy недоступны. Архив содержит секреты только в
зашифрованном виде; ключ в него не включён. Имя выходного файла должно быть
новым, а каталог — вне дерева приложения. При ошибке неполный файл удаляется.

Для тестового запуска и проверки парольного входа есть `restore-smoke.mjs`.
Он проверяет открытие страниц, а не полноту содержимого каждой базы.
Перенеси архив и отдельно ключ за пределы VPS до удаления исходных данных.

Проверить ключ и архив, а затем распаковать его в **новый, ещё не существующий каталог**
отдельной тестовой установки можно так:

```sh
sudo /usr/local/bin/nexus404-node /opt/nexus404/tools/backup/restore-check.mjs \
  /srv/nexus404-backups/manual-YYYYMMDDTHHMMSSZ.nexus /root/nexus404-backup/key
sudo /usr/local/bin/nexus404-node /opt/nexus404/tools/backup/restore-check.mjs \
  /srv/nexus404-backups/manual-YYYYMMDDTHHMMSSZ.nexus /root/nexus404-backup/key \
  /srv/nexus404-restore-test
```

Распаковка не включает переключение действующей установки. Следующий этап —
подъём отдельного хаба из этого каталога и проверка входа и данных модулей.

- `02-hub/` — ядро хаба, общие службы, интерфейс, зависимости контейнера и готовый APK.
- `tools/backup/` — резервное копирование и проверка восстановления.

На установленном сервере хаб — `/opt/nexus404/hub-platform`; `config/` и `data/` содержат рабочие данные. Caddy — `/var/lib/nexus404-caddy`; состояние установки — `/var/lib/nexus404-shell`. Эти каталоги не входят в выпуск и не должны удаляться при замене исходников.

Архив распаковывается в пустой каталог. В репозитории заменяется дерево исходников, включая удаления; распаковка поверх старого дерева сама не уберёт старые тесты и материалы разработки. Сначала сохрани свои изменения. Исходники Android и тесты теперь поставляются отдельно.

## Арго: панель и нода устанавливаются отдельно

На сервере с уже установленным хабом:

```sh
sudo sh menu.sh --vpn-panel
```

Это раздел «VPN и удалённый VPS → Панель Арго». Устанавливается только панель и отдельная база данных VPN. Ядро Xray не устанавливается. В Атланте создай код регистрации нового VPS.

На отдельном VPS Debian/Ubuntu:

```sh
sudo sh menu.sh --vpn-node
```

Это раздел «VPN и удалённый VPS → VPN-нода»: регистрация агента → VPN-ядро, TLS и порты. Базовая настройка запускается отдельно в разделе «Подготовка сервера». Введи HTTPS-адрес хаба и одноразовый код. Хаб, его модули, Docker и Caddy на ноду не устанавливаются. Для Trojan/Hysteria 2 выбери выпуск TLS: домен должен указывать на VPS, порт 80 должен быть доступен для продления. Порты VPN (например 443/tcp и 443/udp) разрешаются в скрипте; для других портов повтори этот пункт. Для Reality сертификат не нужен.

В Арго: «Серверы и подключения» → подключить агент → создать подключение → создать пользователя → выдать подписку. После изменения дождись статуса «Применены» с актуальным номером версии. Для выборочной маршрутизации назначь пользователю профиль и импортируй основную подписку Xray JSON (/xray) в Happ. После изменения правил обнови подписку и переподключись. URI сами по себе правила не переносят.

Обычный мониторинговый агент по-прежнему устанавливается через `--agent`; установка полного хаба сохранена. Обновление не сбрасывает регистрацию, пользователей, расход и расписания.

Арго 0.35.152 — пробная реализация. Цели совместимости: Xray 26.9.30 и Mihomo 1.19.31. Локальные проверки не подтверждают реальные соединения на VPS/в клиентских приложениях. Полный протокол приёмки и ограничения учёта — в `development/docs/VPN.md`.

## Обновление Арго · 0.35.152

Распакуй архив на хабе и на VPN-ноде. Из каталога проекта:

На хабе: `sudo env -u NEXUS_REPO sh ./menu.sh --vpn-panel`

На уже установленной VPN-ноде: `sudo env -u NEXUS_REPO sh ./menu.sh --vpn-update`

Обновление ноды сохраняет регистрацию и текущий TLS, перезапускает VPN-службу.
Нужны обе части обновления. Краткий разрыв при смене протокола ожидаем.

Параметры SNI для Reality и TLS сохраняются раздельно. При переходе к
Hysteria 2 панель подставляет имя/IP из сертификата ноды, если оно известно;
домен маскировки Reality не переносится. Ключи Reality сохраняются при смене
протокола. Нода сообщает наличие сертификата и точную ошибку его проверки.
До подтверждения запуска подписка использует последнее подтверждённое
подключение. Неудачная проверка без изменений прав пользователей сохраняет
работающее ядро; после ошибки запуска восстанавливаются прежние параметры
с учётом текущих ограничений доступа.

Если TLS отсутствует, выпусти сертификат на IP/свой домен через
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-node`. Для Hysteria 2 нужен
разрешённый UDP-порт подключения (например 443/udp), в том числе в панели VPS.
Сертификат проверяется; автоматического отключения проверки TLS нет.

После сохранения дождись «Применены» с текущим номером настроек в Арго.
Затем обнови существующую подписку /xray в Happ и переподключись. Хаб не
может принудительно обновить уже загруженную конфигурацию приложения.
«Применены» означает успешный запуск ядра, а не проверку внешнего UDP-порта.

Выборочная маршрутизация сохранена: указанные домены/IP через VPN,
остальной TCP и UDP напрямую; исключения первыми. При пустом профиле всё
напрямую. DNS берётся из профиля и не гарантирует DNS через тот же выход,
что и сайт. Клиентский JSON сохраняет совместимую структуру Remnawave
(SOCKS 10808, HTTP 10809, sniffing routeOnly=false, IPIfNonMatch).
Пользователи, токены, ключи и расход сохраняются в существующей базе.

Проверки выполняются локально. Установка на Linux VPS и работа конкретной
версии Happ должны проверяться после обновления на своей ноде.


### Статус применения · 0.35.152

При «19 / 20» новое изменение сохранено, но его запуск ещё не подтверждён.
Теперь в этом состоянии выводится «Ожидается подтверждение ноды», а не
«Применены». Успешный статус требует совпадения версий, свежего отчёта и
работающего ядра. Экран обновляется раз в 3 секунды. Отказы и отсутствие
связи показываются отдельно от ожидания.

Для исправления отображения поверх 0.35.147 достаточно обновить хаб через
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-panel`.
Нода 0.35.147 совместима. Этот выпуск не меняет протокол обмена или ядро.
Если расхождение версий держится дольше минуты, одного текста статуса
недостаточно для установления причины: нужны свежий статус Арго и события
агента в Атланте/Гермесе. Не требуется заново менять протокол ради обновления
страницы. Незавершённый интервал учёта — возможная потеря части статистики
при остановке/перезапуске, а не сам по себе отказ транспорта.


### Страны серверов · 0.35.152

На хабе обновить панель из этого архива:
`sudo env -u NEXUS_REPO sh ./menu.sh --vpn-panel`.
VPN-ноды обновлять не требуется.

Арго → Серверы и подключения → Страна в карточке сервера. Выбери страну
или регион с флагом и сохрани. При подключении нового сервера страна также
доступна в форме. Она применяется ко всем подключениям выбранной ноды.
Можно выбрать «Не указана», чтобы убрать страну. Автоопределения по IP нет.

Подписки Xray/Happ, Mihomo и отдельные URI/base64 сразу получают подписи
вида «🇵🇱 Польша · Poland». Уже импортированную подписку нужно обновить
в приложении. Страна — только подпись, она не меняет географию выхода.
Смена страны не меняет ключи, правила, ревизию VPN-ноды и не перезапускает
ядро. Даже при ожидающем применении транспорта меняется только подпись,
последняя подтверждённая конфигурация соединения сохраняется.
Флаги в названиях — Unicode emoji; их вид зависит от шрифтов приложения.
