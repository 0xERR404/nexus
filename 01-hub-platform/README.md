# 01-hub-platform

Docker + Caddy + хаб (Fastify/TypeScript) + модули (каждый — свой
Docker-контейнер). Идёт **после** `00-base-server`.

Персонаж («Рей»), долговременная память, function calling и сжатие истории
были и убраны осознанно — хаб сейчас: голый чат с выбором ИИ/модели + сетка
карточек модулей на главной. Подробности архитектуры и текущий список
модулей — ниже, разделы «Архитектура» и «Модули».

## Установка

На сервере, где уже прогнан `00-base-server`:

```bash
cd nexus/01-hub-platform
sudo bash install-hub-platform.sh
```

Скрипт сам спросит домен в процессе установки (или возьми его заранее:
`PRESET_DOMAIN=hub.example.com sudo -E bash install-hub-platform.sh`).

Прогресс сохраняется в `/var/lib/nexus404-hub/state` — можно перезапускать
скрипт, уже сделанные шаги не повторяются.

## Обновление после git pull

`install-hub-platform.sh` не подходит для обновления — он специально
пропускает уже выполненные шаги (не переспрашивает домен, не пересоздаёт
всё с нуля). Для обновления кода (хаб, модули, Caddyfile) — отдельный
скрипт:

```bash
cd nexus && git pull
cd 01-hub-platform
sudo bash update.sh
```

Копирует изменённые файлы поверх, пересобирает только образ хаба (Caddy —
готовый образ, ему просто перезапуск для перечитывания Caddyfile), не
трогает состояние/прогресс установки.

## Проверка

```bash
curl https://ваш-домен/health
# {"status":"ok","version":"1.5.2","uptime_seconds":N}
```

Браузер будет ругаться на сертификат — это ожидаемо (staging CA), не баг.

## Общий механизм событий (хуки)

Не список из заранее придуманных типов — любой код может сказать «вот что-то
случилось, запиши» с любым новым типом события:

```bash
/opt/nexus404/hooks/event_hook.sh "тип.события" "детали в свободной форме"
```

Один файл-журнал (`/opt/nexus404/hooks/events/events.jsonl`) читают и пишут
одновременно: bash-хук (события сервера — fail2ban, обновления, рестарт,
очистка) и сам хаб (`hub.started`/`hub.stopping` пока что, дальше — события
модулей). Ротация — через `logrotate`, еженедельно, 8 архивов.

## Страница входа

Полноценная, часть самого хаба — не просто `basic_auth` от Caddy:

- `GET /login` — терминальная стилистика (тёмный фон, `IBM Plex Mono`,
  фиолетовый акцент, скан-линии, мигающий курсор)
- `POST /api/auth/login` — проверка пароля (bcrypt, тот же хэш, что и у
  временной защиты Caddy), выдаёт подписанную HMAC-куку сессии
  (`HttpOnly`, `Secure`, `SameSite=Strict`, 30 дней)
- `POST /api/auth/logout` — сброс сессии
- Закрывает **вообще всё** без исключений (глобальный `preHandler`) — даже
  `/health`, никакого аварийного входа. Единственные публичные пути:
  `GET /login` и `POST /api/auth/login`. `/internal/*` (модуль → хаб) —
  отдельная категория, не браузерная сессия, защищена только-localhost
  проверкой

Обе защиты (новая страница входа и старая `basic_auth` в Caddy) держались
параллельно на переходный период. `basic_auth` уже отключён — страница
входа доказала себя вживую (полный цикл проверен: без сессии → редирект →
неверный пароль → 401 → верный пароль → доступ есть → без сессии снова
закрыто). Блок `basic_auth` оставлен закомментированным в `Caddyfile` на
случай, если понадобится снова временно закрыть домен ещё одним слоем.

Проверено вживую, включая уязвимости зависимостей: `fastify` был обновлён
с v4 на v5.12.1 после `npm audit` нашёл 2 high severity уязвимости (DoS,
спуфинг `X-Forwarded-*`) — в v4 патча нет, только в v5.

## Архитектура

```
hub/src/
  index.ts            — Fastify: роуты, прокси /modules/:name/*, /health, /internal/*
  auth.ts              — логин (bcrypt), сессионная HMAC-кука
  dashboard.ts         — HTML+CSS+JS главной страницы и /chat (общий BASE_STYLES)
  moduleSupervisor.ts  — сканирует modules/, собирает/держит живыми через host-bridge
  hostBridge.ts        — клиент к host-bridge.sock (privileged-действия)
  keys.ts              — API-ключи провайдеров (файл, не БД)
  eventWatcher.ts      — раз в 5с читает events.jsonl → push
  push.ts              — Web Push (VAPID)
  chat/                — по файлу на провайдера (deepseek/gemini/claude/flowmusic) + storage/context/usage

modules/<name>/
  Dockerfile, package.json, manifest.json (name/displayName/version/description/port)
  index.js   — raw node:http, без фреймворка, свои роуты + GET /health
  chrome.js  — общая шапка/стили (renderPage) — см. ниже, обязана быть идентичной везде

host-bridge/  — Python-демон НА ХОСТЕ (не в контейнере), слушает unix-сокет,
                белый список действий (build/run/inspect/stop модуля, restart_server,
                run_cleanup) — единственный способ хаба тронуть что-то на уровне хоста,
                без прямого docker.sock (тот = root на хосте)
agent/        — Python-агент для удалённых серверов (метрики + события в monitoring/notifications)
```

Модуль хаб находит сам — сканирует `modules/` раз в 10с, у кого есть валидный
`manifest.json` + `Dockerfile`, того собирает и держит живым через host-bridge
(health-check раз в 5с, до 5 неудач подряд → "broken", дальше retry раз в 2 мин).
**Новый модуль = новая папка** с этими тремя файлами — карточка на главной
появляется сама, без правок хаба.

Каждый модуль получает свою постоянную папку `/app/data` (bind-mount на хосте,
переживает `docker rm -f`) — там держит собственные файлы (JSON/JSONL), без БД.

## Модули (порты 4001–4006)

| Модуль | Порт | Что делает |
|---|---|---|
| technical | 4001 | Ключи API (DeepSeek/Gemini/Claude/FlowMusic/Steam/RetroAchievements), привилегированные действия через хаб |
| billing | 4002 | Баланс DeepSeek + расход токенов по всем 4 провайдерам чата (час/сутки/всё время) |
| notifications | 4003 | Журнал событий сервера + push на телефон (локально и с удалённых серверов) |
| monitoring | 4004 | CPU/RAM/диск/сеть — свой сервер + удалённые агенты, графики за 24ч, сбор раз в 5с |
| finance | 4005 | Учёт денег: карта/депозит (перевод между ними, не независимые деньги), курсы валют/крипты, история операций с редактированием/удалением |
| cheevoscope | 4006 | Статистика игровой библиотеки: Steam (список игр, достижения, цены, отзывы, редкость) + RetroAchievements (профиль, прогресс, очки по консолям) — две вкладки + общая сводка. Изначально отдельный Python/FastAPI-проект — вся логика переписана на Node (единственный не-Node модуль стал бы исключением из общего соглашения проекта), деплой-обвязка (свой install.sh на 1300+ строк, systemd, Caddy, своя авторизация) убрана целиком — не нужна внутри уже существующей инфраструктуры хаба |

## Чат

Отдельная страница `/chat`, живёт в самом хабе (не Docker-модуль). 4 провайдера:
**DeepSeek** (+ выбор модели Flash/Pro — свойство сообщения, не темы, можно
менять посреди разговора), **Gemini**, **Claude**, **FlowMusic** (аудио,
результат — `!audio(url)` в тексте). У каждого провайдера — свой отдельный
список тем. Без персонажа и долговременной памяти — было и осознанно убрано.

Блоки кода (тройные кавычки с указанием языка) в ответах рендерятся отдельной
карточкой с подсветкой языка и кнопками «копировать»/«скачать» (реальный
файл нужного расширения, формируется в браузере).

## Общие приёмы оформления — важно соблюдать при правках

- **Полосатый фон** (`--pattern-bg`, `body::before`) — на каждой странице. У
  sticky-элементов (шапка, поле ввода, панель инструментов чата) — этот же
  паттерн ДОБАВЛЕН поверх сплошного `var(--bg)` (`background: var(--pattern-bg), var(--bg)`),
  не просто сплошной цвет — иначе видна плоская "заплатка" на полосатом фоне.
- **`position: sticky`, не fixed-height/`100dvh`** — фиксированная высота
  экрана в JS (`window.innerHeight`) ломалась на части Android-прошивок.
  Шапка/панели/поле ввода — просто `sticky`, вся страница — обычный
  прокручиваемый поток, как везде.
- **6 копий `chrome.js`** (`_shared/` — эталон, плюс по одной на каждый из 5
  модулей) обязаны быть **побайтово идентичны** — правишь общий вид, правь
  во всех шести, `_shared/` используется только при создании нового модуля,
  Dockerfile-ы копируют СВОЮ локальную копию, не `_shared/`.
- **Версия** — одно число, синхронизируется разом: `hub/package.json`,
  `package-lock.json` (через `npm install --package-lock-only`, не руками),
  все 5 `manifest.json`, пример в этом README (`## Проверка` выше).
- **Скролл-толчок** (`window.scrollTo` на `load`, есть у всех страниц) —
  сдвигает на 1px и возвращает на ТЕКУЩУЮ позицию (`window.scrollY`), не
  жёсткий `0` — иначе перебивает честный автоскролл чата к последнему
  сообщению, если тот успел отработать раньше.

## Честные оговорки (не баги, ограничения источников)

- **Баланс DeepSeek** — настоящий REST-эндпоинт, есть. У Gemini/Claude/
  FlowMusic такого API нет вообще — billing показывает статус по факту
  последнего запроса в чате (`ok`/`лимит`/`нет ключа`), не выдуманную цифру.
- **Курсы валют/крипты** (finance) — единственные внешние HTTP-запросы,
  которые модуль делает НАПРЯМУЮ, не через хаб: там нет секрета (публичные
  API, ЦБ РФ и CoinGecko), проксировать через хаб было бы прослойкой без
  смысла (в отличие от ключей провайдеров чата).
- **Логаут** — не настоящая инвалидация сессии (stateless HMAC-подпись, хаб
  не хранит список активных сессий), просто чистит cookie у браузера.
- **Ключи CheevoScope** (Steam/RA) — единственные, где модуль получает
  сырое значение ключа от хаба (`GET /internal/cheevoscope-keys`), не
  обработанный результат, как у чат-провайдеров: модуль сам обращается к
  Steam/RA API напрямую, хабу нечего было бы обработать вместо него.
  Спрашиваются заново перед каждым прогоном (`quick`/`full`), не
  кэшируются в процессе — смена ключей в интерфейсе действует со
  следующего запуска, без пересоздания контейнера.

## Деплой-скрипты

`00-base-server/nexus404-base-setup.sh`, `01-hub-platform/install-hub-platform.sh`,
`01-hub-platform/update.sh` — три независимых `curl | bash` файла (общий модуль
подключить неоткуда), но общий код (спиннер с таймером `_spin_wait`/`run_spinner`,
`enable_full_logging`, `is_done`/`mark_done`) должен оставаться **дословно
одинаковым** — правишь в одном, переноси в остальные два вручную.

## Как вносить изменения — не только "что", но и "как"

Это не пожелание на будущее, а то, каким способом реально сделаны все
правки в этом проекте до сих пор. Отступление от этого — не экономия
времени, а перекладывание работы на кого-то потом (в том числе на себя
в следующем чате).

- **Не гадать по памяти/названию — открыть реальный текущий файл** перед
  любым утверждением о том, как что-то устроено. Комментарии и этот
  README могут отставать от кода; единственный источник правды — сам код.
- **Каждую правку — реально проверять, не только глазами по коду.**
  TS — `npx tsc --noEmit` после каждого изменения, не одной пачкой в
  конце. JS-модули — `node --check`. Shell-скрипты — `bash -n`. Реальную
  логику (не только синтаксис) — поднять модуль/хаб локально и постучаться
  настоящим `curl`, не предполагать по чтению кода, что оно сработает.
  Для проверок безопасности (XSS, инъекции) — через реальный DOM
  (jsdom), не только визуальный осмотр экранирования.
- **Версия — одно число, сразу везде за одну операцию**, не по частям:
  `hub/package.json`, `package-lock.json` (`npm install
  --package-lock-only`, не руками), все `manifest.json`, пример в этом
  README. Расхождение хотя бы в одном месте — то же самое, что не
  обновить вообще.
- **6 копий `chrome.js` — правишь один раз в `_shared/`, копируешь во все
  пять остальных**, не редактируешь каждую копию вручную по отдельности
  (разъедутся). Проверка после — `md5sum` на все шесть, должны совпасть.
- **Комментарии — лаконично, объясняют "почему", не пересказывают историю
  правок.** Не "было так, стало так после такой-то жалобы, а до этого
  пробовали иначе" — только актуальная причина того, что видно в коде
  сейчас. История разработки — не место комментариям, если она вообще
  где-то нужна, то не в коде.
- **Этот README — справочник текущего состояния, не журнал изменений.**
  Добавился модуль/провайдер/приём оформления — обнови таблицу/раздел
  здесь тем же заходом, не отдельным "потом". Если правка меняет то, что
  написано в README (например, число модулей, версия в примере
  `/health`, список провайдеров чата) — README считается частью самой
  правки, не факультативным довеском.
- **Честно предупреждать о непроверенном**, а не молчать. В песочнице
  нет сети до внешних API (DeepSeek/Gemini/CoinGecko и т.п.) — если
  что-то не проверено живым запросом, так и сказать прямо в ответе и в
  комментарии рядом с кодом, не выдавать предположение за факт.
