# flowmusic-keeper

Держит реальный Chromium (не подмену TLS-отпечатка, как `impit` в
`chat/providers.ts`, а настоящую вкладку) залогиненным на
`flowmusic.app`. Пока вкладка открыта, встроенный JS-клиент Supabase на
самой странице сам продлевает `access_token` заранее — тот же механизм,
что у обычного пользователя, который просто держит сайт открытым. Раз в
2 минуты модуль читает актуальную куку сессии и передаёт её хабу через
`POST /internal/flowmusic-session` — тот же формат, что при ручной
вставке в настройках, `chat/providers.ts` разбирает сам, ничего не
дублируется.

## Установка

1. Скопировать эту папку в `nexus/01-hub-platform/modules/flowmusic-keeper/`.
2. Применить `hub-patch.md` к `hub/src/index.ts` (один новый роут).
3. Синхронизировать версию везде (см. `## Версия` в `hub-patch.md`).
4. `git add -A && git commit ... && git push`.
5. На сервере: `cd nexus && git pull && cd 01-hub-platform && sudo bash update.sh`.
6. Хаб сам обнаружит новую папку (сканирует `modules/` раз в 10с),
   соберёт образ и запустит — без правок `moduleSupervisor.ts`.
7. Открыть `/modules/flowmusic-keeper/` в хабе, вставить в поле
   «Затравка» текущую куку `sb-sb-auth-token` с flowmusic.app (DevTools
   → Application → Cookies) — то же значение, что раньше вставлял(а) в
   настройках хаба вручную. Дальше — само.

## Честные оговорки (не баги, ограничения источника)

- **Имя куки для затравки не проверено живым запросом** (в песочнице
  разработки нет сети до flowmusic.app). Дефолт `sb-sb-auth-token`
  выведен из того же места, что и в `providers.ts` (apikey = поддомен
  `sb.producer.ai` = `sb`) — по аналогии с примером в его комментариях
  ("sb-sb-auth-token.0"), не факт напрямую. Если после вставки статус
  на странице модуля остаётся `needs_seed` — открой DevTools на
  flowmusic.app и проверь точное имя куки, задай его через переменную
  окружения `FLOWMUSIC_COOKIE_NAME` в `docker-compose`/манифесте
  контейнера (без правки кода).
- **Не проверено, что Supabase-клиент на странице действительно
  продлевает токен именно через cookie, а не только localStorage** —
  `@justmpm/flowmusic` (сторонний референс, на который опирается и сам
  хаб) читает оба места как fallback, поэтому теоретически возможно,
  что автообновление там завязано на localStorage, а не куку. Если
  `access_token` в куке, которую видит модуль, не меняется со временем
  (проверяется через `/state` — `lastSyncAt` растёт, но фактическое
  значение куки на flowmusic.app в DevTools остаётся тем же) — вероятно,
  нужно читать `localStorage` вместо cookie (`page.evaluate(() =>
  Object.entries(localStorage))`), это не реализовано в первой версии.
- **Один общий браузерный профиль на весь хаб**, как и токен FlowMusic
  в `keys.json` — так же, как FlowMusic-провайдер в чате уже общий на
  весь хаб, не по темам (см. `providers.ts`).
- **Alpine Chromium (`apk add chromium`) тяжелее остальных модулей** —
  образ вырастет примерно на 300+ МБ, это осознанное отступление от
  принципа «максимально лёгкие модули», необходимое именно для того,
  чтобы получить настоящий браузер, а не только заголовки.
- **Пуш-алерт при `logged_out`/повторных ошибках sync** идёт через уже
  существующий `POST /internal/send-push` (тот же путь, что и у
  notifications) — новых точек интеграции с push не добавлено.
